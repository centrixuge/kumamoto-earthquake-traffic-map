# 熊本地震・交通量変化ダッシュボード (kumamoto-earthquake-traffic-map)

[![Open in Streamlit](https://static.streamlit.io/badges/streamlit_badge_black_white.svg)](https://kumamoto-earthquake-traffic-map.streamlit.app/)

**🔗 公開URL: https://kumamoto-earthquake-traffic-map.streamlit.app/**

2026年7月28日16:27頃に熊本地方で発生した地震（M7.1・最大震度7）の前後で、**交通量と通行規制を同じ画面で突き合わせて見る**ためのダッシュボードです。どこが止まっていて、そのとき近くの交通量がどうなっていたのかを、公開データだけで追えるようにしています。

- **地図と、交通量の時系列変化のグラフを並べて出します**。地図には常時観測点（12点）の異常度と通行規制を重ね、観測点を選ぶと、その地点の交通量が平常時と比べてどう推移したかが隣のグラフに出ます。地図上で規制の位置と時刻を確かめながら、同じ時間帯の交通量を読む使い方を想定しています
- **通行規制は3つの経路から集めています**。県の公開JSON（県・市町村が管理する道路。補助国道・県道・市町村道）に加え、配信の仕組みが無い直轄国道・高速道路はPDFから転記しました。1つのポータルにまとまっていない規制を、1枚の地図に載せています
- 平常時（同じ日区分・同じ時刻）との比較による**簡易異常検知**の結果を、地図の色分けと交通量のグラフに出します（**対象は発災後1週間**。それ以降はお盆にかかり、地震前の平常時と比べる意味が薄いため）
- 通行規制の出所が違う**2つのタブ**があり、同じ観測点・同じグラフのまま規制の見え方だけを比べられます（既定は国の配布データ、（参考）は県の公開JSON＋PDFからの転記）

## ねらい

災害直後の交通量の変化と、その背景にある通行規制を、**公開データだけで・発災当日から・後から検証できる形で**残すことを目的にしています。

- **公開データのみ**: 認証やAPIキー、有償契約を必要としないデータだけで構成しています。誰でも同じ手順で再現・検証できることを優先しました
- **取れるうちに残す**: JARTICの5分値は過去1ヶ月分しか遡れず、通行規制は解除されるとポータルの一覧から消えます。そのため取得した生データを**追記専用でアーカイブ**し、後から遡って分析できるようにしています（[docs/data-pipeline.md](docs/data-pipeline.md)）
- **判断の根拠を明示する**: 「平常時」の定義や異常判定のしきい値、代替指標を使っている箇所を README とダッシュボード上の両方に書いています。数字だけを見せて解釈を委ねる状態にしないことを意図しています
- **復旧期まで追う**: 発災直後だけでなく、交通が平常に戻っていく過程まで対象期間に含めています

## できること

| タブ | 内容 |
| --- | --- |
| 地図・交通量の時系列変化 | 常時観測点別の異常度（zスコア）と通行規制情報を地図上に重ね合わせ、選択した観測点（最大2地点）の交通量の時系列変化（平常時 vs 観測実績）を並べて表示。粒度（5分間値／1時間値）・車種別表示・表示期間の切り替えができます。**通行規制は国土交通省「通れる道マップ」の配布GeoJSON**で、レイヤは道路種別（高速自動車国道／一般国道／県道・市区町村道）×状態（規制中／解除済み）。規制の一覧はCSV・GeoJSONで取得できます |
| 地図・交通量の時系列変化（参考） | 同じ並び・同じ操作で、**通行規制だけ**を県の公開JSON＋PDFからの転記に差し替えた版。地震前からの規制や、直轄国道・高速道路の報の中身（緊急車両の通行可能区間など）はこちらにしかありません |
| データダウンロード | 5つのデータセット（交通量の5分値・1時間値、通行規制の一覧・状態変化履歴、異常検知の入力データ）を**内容・行数・期間・対応する列定義書のシート名を並べた一覧表**から選んでCSVで取得。各列の意味・単位をまとめた**列定義書**をExcel（1シート＝1データセット）でダウンロードできます（実データの列と自動照合し、食い違いがあるときだけ理由付きの備考を表示します） |

観測点は**地図上のマーカーをクリック**するか、**画面上部のプルダウンから選択**するかのどちらでも選べます。規制は3つの軸で描き分けており、それぞれ独立しています。**色＝規制の区分**（赤＝全面/車両通行止め、橙＝片側交互など、青灰＝地震前からの規制）、**⊗の有無＝今回の地震以降に始まったかどうか**（PDFの別添図と同じ記号。色は区分に従います）、**実線／破線＝いま規制中か解除済みか**（線も⊗の外円も同じ）。さらに、場所が区間で示されているものは線＋⊗、地点でしか分からないものは⊗のみで置いています。この描き分けは道路の管理者によらず共通で、県・市町村管理の道路でも直轄国道でも高速道路でも同じです。規制のレイヤは**道路の管理者×状態**で分けてあり（高速道路／直轄国道／県・市町村管理 × 規制中／解除済み／地震前から）、地図の右下の「≡ レイヤ」にマウスを載せると一覧が開き、そこで切り替えられます（規制の線にかぶらないよう、たたんだ状態で置いています）。**既定では「規制中」だけを表示**し、解除済みと地震前からの規制はオフにしています（記録している規制の多くはすでに解除済みで、まとめて出すといま何が止まっているのかが読み取れないためです）。区間の端点（IC）はその区間と同じレイヤに入っているので、区間を消せば一緒に消えます。規制の凡例は地図の下に置いています。観測点のマーカーは、色の濃さと大きさが異常度、**形が道路の種別**（●＝一般国道／■＝高速自動車国道）です。この種別はJARTICが返す`道路種別`をそのまま使っており、道路の法的な位置づけを表すものではありません（地図の中の凡例では「観測点の道路種別」として示しています）。形の凡例は地図を見ながら参照するものなので**地図の中**（右上）に置いています。

**（参考）でない既定のタブ**（通れる道マップの配布データ）は、観測点・異常度・交通量のグラフは同じまま、規制の描き分けだけが違います。**色＝道路種別**（高速自動車国道／一般国道／県道・市区町村道）、**破線＝解除済み**で、レイヤは段階×状態です。状態は配布データを時点ごとに突き合わせて決めており、最新時点にも残っていれば規制中、途中で消えていれば解除済みとしています（解除の時刻は配布の間隔ぶん粗くなります）。道路種別が取れない件（配布GeoJSONに線形だけが入っていて属性を持たないもの）は、**地図では「規制中」として出さず、解除済みの扱いで残します**（レイヤ一覧の「不明：解除済み」で切り替え、既定は非表示）。配布元の地図でも凡例に無い紫色で描かれ、いまの配布分については不備と見られるためで、そこに規制があったという記録は消さずに残しています。

## データソース

| データ | 提供元 | 補足 |
| --- | --- | --- |
| 常時観測点の5分間交通量／1時間交通量 | [JARTIC 交通量オープンデータ](https://www.jartic-open-traffic.org/) | [WFS APIの仕様書(PDF)](https://www.jartic-open-traffic.org/action_method.pdf)に基づき取得。認証・APIキー不要。5分値は過去1ヶ月・1時間値は過去3ヶ月まで遡れる。観測点は両者でほぼ同一。道路種別（1＝高速自動車国道 / 3＝一般国道）ごとに別リクエストで、両方を取得している（現在の対象エリアでは一般国道9点・高速自動車国道3点の計12点）。**返るのは台数のみで、速度・旅行時間・占有率は提供されていない** |
| 地震情報（震源・マグニチュード・市町村別最大震度） | 気象庁が公開している防災情報JSON (`https://www.jma.go.jp/bosai/quake/data/list.json`) | 公式なAPI仕様として文書化されたものではなく、気象庁ウェブサイトの表示に使われている公開JSONを利用（多くの防災アプリ・サイトで実利用されている形式）。同一地震に複数の報が出るため、報を統合して最新の非空値を採用している |
| 道路通行規制情報（県・市町村が管理する道路＝**補助国道・県道・市町村道**） | 熊本県「[防災情報くまもと](https://portal.bousai.pref.kumamoto.jp/)」の[通行規制情報](https://portal.bousai.pref.kumamoto.jp/?p=traffic)ページが使う公開JSON (`https://portal.bousai.pref.kumamoto.jp/data/traffic/traffic.json`) | 認証不要。[熊本市防災情報ポータル](https://city-kumamoto.my.salesforce-sites.com/)からもリンクあり。始点・終点の座標のみのため、[OSRM](https://project-osrm.org/) の公開デモサーバーで実際の道路網に沿った経路にスナップして地図に表示。**県が管理する補助国道（国道218/219/265/266/324/442/443/445号）も入ります**（65件中15件） |
| 道路通行規制情報（**直轄国道・直轄の高規格道路**） | 国土交通省 九州地方整備局 [熊本河川国道事務所](https://www.qsr.mlit.go.jp/kumamoto/)の「事務所からのお知らせ」で公表されるPDF（道第○報） | **上のポータルには国が管理する道路の規制が載らない**ため、PDFから**手作業で転記**して `data/mlit_regulations.json` に持っています（8件）。自動取得ではありません。転記元のPDFは [`data/qsr_regulations/`](data/qsr_regulations) に置いています |
| 道路通行規制情報（**高速道路＝NEXCO西日本が管理する高速自動車国道など**） | [NEXCO西日本](https://www.w-nexco.co.jp/) 九州支社が公表するPDF（「令和8年熊本地震による通行止め・災害状況等について」第○報） | 高速道路も配信の仕組みがないため、同じくPDFから**手作業で転記**して `data/nexco_regulations.json` に持っています（8件）。転記元のPDFは [`data/nexco_west_regulations/`](data/nexco_west_regulations) に置いています。区間の線形はOSMで当該路線のノードを拾って復元しています |
| 道路通行規制情報（**通れる道マップ版・既定のタブ**） | 国土交通省「[通れる道マップ](https://www.mlit.go.jp/road/saigai/r8kumamoto/index.html)」が各時点で配布するGeoJSON（ZIP） | 上の3経路とは**別系統**のデータで、既定のタブで使っています。28ファイル（うち規制情報は27時点）を [`data/mlit_r8kumamoto_map/`](data/mlit_r8kumamoto_map) に保存し、[`scripts/build_mlit_map_regulations.py`](scripts/build_mlit_map_regulations.py) で時点をまたいで突き合わせ、通算110件にまとめています（[docs/mlit-map.md](docs/mlit-map.md)） |

通行規制の3つの経路は、ダッシュボードの地図の下にも同じ形の表（出典ページと収集済みデータへのリンク付き）で出しています。詳しい欠落の理由（管理者の違い・収集開始が本震より後）と、直轄国道8件・高速道路8件の転記内容・手順は **[docs/regulations.md](docs/regulations.md)** にまとめています。

> **交通量が0でも、その原因の規制が地図に出てこない場合があります。** 県のデータは県・市町村が管理する道路が対象で直轄国道も高速道路も含まず、また規制の収集を始めたのが本震の翌日のため、それ以前に解除された規制は残っていません。

## 手法・注意点

平常時は**日区分ごとに別々**の1時間交通量から作り、実測はその日と同じ日区分と比べます（月・火・水・木・金は各曜日で、土は土、日曜と祝日は「日祝」でまとめて各8日分）。異常検知は1時間値どうしの比較で `|zスコア| >= 2` を異常とし（**対象は発災後1週間**）、交通量の時系列変化のグラフは5分間値／1時間値／それぞれの車種別の4通りで見られ、表示期間もプルダウンで切り替えられます（本震からの経過時間で区切っており、既定は発災後1週間）。

**異常検知は原因を特定するものではありません。** 「平常時からの外れ」を機械的に拾っているだけで、地震以外の要因（イベント・天候・工事・機器不調）も同じように異常になります。

曜日を分ける根拠の実測値、車種別で見える差、観測点が12点しかないことなどの制約、対象エリアや期間を決めている定数は **[docs/methods.md](docs/methods.md)** にまとめています。

## データの取得とアーカイブ

JARTICの5分値は**過去1ヶ月分しか遡って取得できない**ため、取得したコマを `data/archive/` に**追記専用**で蓄積し、GitHub Actionsで6時間ごとに自動取得しています。通行規制も解除されると一覧から消えるため同様にアーカイブしています。

アーカイブの設計（既存コマを二重取得しない仕組み、失敗時の扱い）、自動取得の設定、コードの構成とディレクトリ構成は **[docs/data-pipeline.md](docs/data-pipeline.md)** にまとめています。

## セットアップ

### 1. ダッシュボードを見るだけの場合

```bash
pip install -r requirements.txt
streamlit run app.py
```

`data/` 配下に本リポジトリ同梱の前処理済みデータが入っているため、これだけで起動できます。

### 2. データを最新化する場合

```bash
pip install -r requirements.txt -r requirements-fetch.txt
python fetch_and_prepare.py
```
