# 熊本地震・交通量変化ダッシュボード (kumamoto-earthquake-traffic-map)

[![Open in Streamlit](https://static.streamlit.io/badges/streamlit_badge_black_white.svg)](https://kumamoto-earthquake-traffic-map.streamlit.app/)

**🔗 公開URL: https://kumamoto-earthquake-traffic-map.streamlit.app/**

2026年7月28日16:27頃に熊本地方で発生した地震（M7.1・最大震度7）の前後で、交通量が平常時と比べてどう変わったかを観測点ごとに可視化する簡易ダッシュボードです。

> **名称について**: 「行動変容」ではなく「交通量変化」としています。本ツールが持っているのは交通量と通行規制・地震情報だけで、迂回・外出抑制・通勤形態の変化といった**行動の中身やその要因を示すデータは収集していません**。平常時との差が出た理由は本ツールでは特定できません。そうしたデータを扱えるようになった時点で名称を見直します。

- 交通量データと地震情報を重ね合わせ、平常時との比較による**簡易異常検知**を行います
- 観測点をクリックして時系列を比較できるインタラクティブな地図を備えます（最大2地点を選択して比較可能）

## ねらい

災害直後の交通量の変化を、**公開データだけで・発災当日から・後から検証できる形で**残すことを目的にしています。

- **公開データのみ**: 認証やAPIキー、有償契約を必要としないデータだけで構成しています。誰でも同じ手順で再現・検証できることを優先しました
- **取れるうちに残す**: JARTICの5分値は過去1ヶ月分しか遡れず、通行規制は解除されるとポータルの一覧から消えます。そのため取得した生データを**追記専用でアーカイブ**し、後から遡って分析できるようにしています（[docs/data-pipeline.md](docs/data-pipeline.md)）
- **判断の根拠を明示する**: 「平常時」の定義や異常判定のしきい値、代替指標を使っている箇所を README とダッシュボード上の両方に書いています。数字だけを見せて解釈を委ねる状態にしないことを意図しています
- **復旧期まで追う**: 発災直後だけでなく、交通が平常に戻っていく過程まで対象期間に含めています

## できること

| タブ | 内容 |
| --- | --- |
| 地図・時系列 | 常時観測点別の異常度（zスコア）と通行規制情報を地図上に重ね合わせ、選択した観測点（最大2地点）の時系列（平常時 vs 観測実績）を並べて表示。粒度（5分間値／1時間値）・車種別表示・表示期間の切り替えができます |
| 異常検知一覧 | 地震発生後に検知された異常のテーブルとCSVダウンロード |
| データダウンロード | 5つのデータセット（交通量の5分値・1時間値、通行規制の一覧・状態変化履歴、異常検知の入力データ）を**内容・行数・期間・対応する列定義書のシート名を並べた一覧表**から選んでCSVで取得。各列の意味・単位をまとめた**列定義書**をExcel（1シート＝1データセット）でダウンロードできます（実データの列と自動照合し、食い違いがあるときだけ理由付きの備考を表示します） |

観測点は**地図上のマーカーをクリック**するか、**画面上部のプルダウンから選択**するかのどちらでも選べます。規制の描き分けは**色＝規制の区分**（今回の地震以降に始まった全面通行止め／同じく片側交互など／地震前からの規制）、**線の形＝いま規制中か解除済みか**（実線／破線）の2軸で、この2つは独立しています。破線が解除済みを表すのは色にも道路の種別にもよらず共通で、県のフィードにある県道以下の規制でも、別レイヤの直轄国道でも同じです。規制の凡例は地図の上部に置いています。観測点のマーカーは、色の濃さと大きさが異常度、**形が道路の種別**（●＝一般国道／■＝高速自動車国道）です。この種別はJARTICが返す`道路種別`をそのまま使っており、道路の法的な位置づけを表すものではありません（その旨が分かるよう、地図の中の凡例に「JARTICの道路種別」と見出しを付けています）。形の凡例は地図を見ながら参照するものなので**地図の中**（右上）に置いています。

## データソース

| データ | 提供元 | 補足 |
| --- | --- | --- |
| 常時観測点の5分間交通量／1時間交通量 | [JARTIC 交通量オープンデータ](https://www.jartic-open-traffic.org/) | [WFS APIの仕様書(PDF)](https://www.jartic-open-traffic.org/action_method.pdf)に基づき取得。認証・APIキー不要。5分値は過去1ヶ月・1時間値は過去3ヶ月まで遡れる。観測点は両者でほぼ同一。道路種別（1＝高速自動車国道 / 3＝一般国道）ごとに別リクエストで、両方を取得している（現在の対象エリアでは一般国道9点・高速自動車国道3点の計12点）。**返るのは台数のみで、速度・旅行時間・占有率は提供されていない** |
| 地震情報（震源・マグニチュード・市町村別最大震度） | 気象庁が公開している防災情報JSON (`https://www.jma.go.jp/bosai/quake/data/list.json`) | 公式なAPI仕様として文書化されたものではなく、気象庁ウェブサイトの表示に使われている公開JSONを利用（多くの防災アプリ・サイトで実利用されている形式）。同一地震に複数の報が出るため、報を統合して最新の非空値を採用している |
| 道路通行規制情報（県・市町村が管理する道路） | 熊本県「[防災情報くまもと](https://portal.bousai.pref.kumamoto.jp/)」の[通行規制情報](https://portal.bousai.pref.kumamoto.jp/?p=traffic)ページが使う公開JSON (`https://portal.bousai.pref.kumamoto.jp/data/traffic/traffic.json`) | 認証不要。[熊本市防災情報ポータル](https://city-kumamoto.my.salesforce-sites.com/)からもリンクあり。始点・終点の座標のみのため、[OSRM](https://project-osrm.org/) の公開デモサーバーで実際の道路網に沿った経路にスナップして地図に表示 |
| 道路通行規制情報（**直轄国道・高規格道路**） | 国土交通省 九州地方整備局 [熊本河川国道事務所](https://www.qsr.mlit.go.jp/kumamoto/)の「事務所からのお知らせ」で公表されるPDF（道第○報） | **上のポータルには国が管理する道路の規制が載らない**ため、PDFから**手作業で転記**して `data/mlit_regulations.json` に持っています。自動取得ではありません。転記元のPDFは `data/qsr_regulations/` に保存しています（[docs/regulations.md](docs/regulations.md)） |

詳しい欠落の理由（管理者の違い・収集開始が本震より後）と、直轄国道7件の転記内容・手順は **[docs/regulations.md](docs/regulations.md)** にまとめています。

> **交通量が0でも、その原因の規制が地図に出てこない場合があります。** 県のデータは県・市町村が管理する道路が対象で直轄国道を含まず、また規制の収集を始めたのが本震の翌日のため、それ以前に解除された規制は残っていません。

## 手法・注意点

平常時は**日区分ごとに別々**の1時間交通量から作り、実測はその日と同じ日区分と比べます（月・火・水・木・金は各曜日で、土は土、日曜と祝日は「日祝」でまとめて各8日分）。異常検知は1時間値どうしの比較で `|zスコア| >= 2` を異常とし、時系列図は5分間値／1時間値／それぞれの車種別の4通りで見られ、表示期間もプルダウンで切り替えられます（本震からの経過時間で区切っており、既定は発災後1週間）。

**異常検知は原因を特定するものではありません。** 「平常時からの外れ」を機械的に拾っているだけで、地震以外の要因（イベント・天候・工事・機器不調）も同じように異常になります。

曜日を分ける根拠の実測値、車種別で見える差、観測点が12点しかないことなどの制約、対象エリアや期間を決めている定数は **[docs/methods.md](docs/methods.md)** にまとめています。

## データの取得とアーカイブ

JARTICの5分値は**過去1ヶ月分しか遡って取得できない**ため、取得したコマを `data/archive/` に**追記専用**で蓄積し、GitHub Actionsで6時間ごとに自動取得しています。通行規制も解除されると一覧から消えるため同様にアーカイブしています。

アーカイブの設計（既存コマを二重取得しない仕組み、失敗時の扱い）、自動取得の設定、コードの構成とディレクトリ構成は **[docs/data-pipeline.md](docs/data-pipeline.md)** にまとめています。

## セットアップ

### 1. ダッシュボードを見るだけの場合

```bash
pip install -r requirements.txt
streamlit run app.py
```

`data/` 配下に本リポジトリ同梱の前処理済みデータが入っているため、これだけで起動できます。

### 2. データを最新化する場合

```bash
pip install -r requirements.txt -r requirements-fetch.txt
python fetch_and_prepare.py
```
