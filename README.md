# 熊本地震・交通行動変容ダッシュボード

[![Open in Streamlit](https://static.streamlit.io/badges/streamlit_badge_black_white.svg)](https://kumamoto-earthquake-traffic-map.streamlit.app/)

**🔗 https://kumamoto-earthquake-traffic-map.streamlit.app/**

2026年7月28日16時27分に熊本県熊本地方で発生した地震（M7.1・最大震度7）の前後で、**交通量が平常時からどれだけ外れたか**を観測点ごとに可視化するダッシュボードです。通行規制の情報を地図上で重ね合わせ、「どこで交通量が落ちたか」と「どこが通れなくなったか」を並べて見られるようにしています。

すべて公開データのみで構成しており、認証やAPIキーは不要です。

---

## 1. 何が見えるのか

| タブ | 内容 |
| --- | --- |
| **地図・時系列** | 左に地図（観測点の異常度＋通行規制）、右に選択した観測点の時系列。観測点は**地図のマーカーをクリック**するか**プルダウンから選ぶ**かで、最大2地点まで並べて比較できます |
| **異常検知一覧** | 地震後に異常と判定された時点の一覧とCSVダウンロード |
| **データダウンロード** | アーカイブ済みの交通量・通行規制をCSVで取得。各列の意味をまとめた**列定義書（Excel、データセットごとにシート分け）**も一緒に配布できます。列定義書は実データの列と自動照合され、食い違いがあるときだけ理由付きの備考が表示されます |

### 地図の読み方

- **丸いマーカー**＝常時観測点。色が濃いほど地震後の異常度（後述のzスコア）が大きい。**寒色系**（薄い青→濃紺）
- **赤い線と×印**＝今回の地震以降に始まった**全面通行止め／車両通行止め**
- **オレンジの線**＝今回の地震以降に始まったその他の規制（片側交互通行止めなど）
- **くすんだ青灰色の線**＝地震前からある規制（工事や過去の災害によるもの。今回の地震とは無関係）
- **破線**＝すでに解除済み

規制の色を暖色、異常度を寒色にしているのは、両者が同じ地図の上で混ざらないようにするためです。地震前からの規制を分けて表示しているのは、2020年7月豪雨による通行止めのように**数年前から継続している規制が今回の地震によるものと見分けられなくなる**のを避けるためです（レイヤの表示/非表示は地図右上で切り替えられます）。

### 時系列の読み方

- **実線**＝実績値。**破線**＝平常時の平均。**灰色の帯**＝平常時の±1σ
- 黒い点線＝本震の発生時刻。細い薄色の点線＝最大震度5弱以上を観測した地震の発生時刻
- 上部のラジオボタンで**5分間値（既定）**と**1時間値（参考）**を切り替えられます

## 2. 数字の意味

ここが結果の解釈に直結するので、定義をはっきり書いておきます。

### 「平常時」とは

**本震と同じ曜日（火曜）を8週分さかのぼった1時間交通量**です。観測点×時刻（hour）ごとに平均と標準偏差を求めています。

- **なぜ1時間値か**: 5分間値はAPIで過去1ヶ月しか遡れないのに対し、1時間値は3ヶ月遡れます。平常時の平均・分散は母集団を広く取ったほうが安定するため、遡れる1時間値を使っています
- **祝日は除く**: 交通量の傾向が平日と異なるため、[内閣府の祝日CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)を参照して母集団から外します（該当日がなければ8日分すべて使用。除外内容は実行ログに出ます）
- **1日の区切りは03:00**: 深夜帯を日付でまたいで切らないため

### 「異常」とは

**1時間値どうしの比較**で `|zスコア| >= 2` を異常としています。zスコア＝（実績 − 平常時平均）÷ 平常時標準偏差。**地図の色分けも異常検知一覧も、この1時間値ベースの判定です。**

5分間値ではなく1時間値で判定している理由は、5分間値の平常時が「1時間値の統計量を1/12したもの」で、ばらつきの意味が変わってしまうからです。

### 2つの時系列ビューの違い

| ビュー | 実績 | 平常時 | 用途 |
| --- | --- | --- | --- |
| **5分間値（既定）** | 5分間値 | 1時間値の統計量を1/12 | 発災直後の急変を細かく見る |
| **1時間値（参考）** | 1時間値 | 1時間値 | 異常判定と同じ粒度で確認する |

5分間値ビューの灰色の帯は「**平常時の1時間あたり交通量の日々のばらつき ÷ 12**」であり、5分間値そのもののばらつきではありません。そのため実際より狭く出ます（同梱データ時点では、5分間値どうしで求めたσの平均 8.2 に対して 3.0 程度）。細かい変動を追うのには使えますが、**帯からの外れ具合を異常の根拠にはしないでください**。

### 揺れの強さの扱い

気象庁の推計震度分布データを機械的に取得するのが難しいため、**観測点と震源との距離[km]** を揺れの強さの簡易的な代理指標として持たせています。実際の震度分布とは異なります。

### 観測点のID

JARTICの**常時観測点コード**（例 `9110030`）を観測点の識別子として、地図・セレクタ・グラフ凡例・CSVで共通に使っています。現在の対象エリアには7点あります。

アーカイブにはこの列を持たない時期のデータも含まれるため、`data/stations.json`（コードと緯度経度の対応表）を経由して後から付け直しています。座標はAPIの応答で末尾の桁がわずかに揺れる（`130.757293` と `130.7572925`）ので、5桁≒1mに丸めて突き合わせています。

## 3. データの出どころ

| データ | 提供元 | 補足 |
| --- | --- | --- |
| 常設トラカン **5分間交通量／1時間交通量** | [JARTIC 交通量オープンデータ](https://www.jartic-open-traffic.org/) | [WFS APIの仕様書(PDF)](https://www.jartic-open-traffic.org/action_method.pdf)に基づき取得。認証・APIキー不要。5分値は過去1ヶ月・1時間値は過去3ヶ月まで遡れる。観測点は両者で同一（7点） |
| **地震情報**（震源・マグニチュード・市町村別最大震度） | 気象庁が公開している防災情報JSON (`https://www.jma.go.jp/bosai/quake/data/list.json`) | 公式なAPI仕様として文書化されたものではなく、気象庁ウェブサイトの表示に使われている公開JSON（多くの防災アプリ・サイトで実利用されている形式） |
| **道路通行規制情報**（区間・時間帯・規制理由） | 熊本県「[防災情報くまもと](https://portal.bousai.pref.kumamoto.jp/)」の[通行規制情報](https://portal.bousai.pref.kumamoto.jp/?p=traffic)ページが使う公開JSON | 認証不要。[熊本市防災情報ポータル](https://city-kumamoto.my.salesforce-sites.com/)からもリンクされています。始点・終点の座標のみのため、[OSRM](https://project-osrm.org/) の公開デモサーバーで道路網に沿った経路にスナップして描画 |
| **祝日** | [内閣府 国民の祝日CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv) | 平常時の母集団から祝日を外すために使用（Shift_JIS） |

### 使えなかったデータ

**通行実績情報**（実際に車が通れた道の情報）は重ね合わせたかったものの、無償でAPI取得・ダウンロードできる形では見つかりませんでした。トヨタ・ホンダの通行実績マップは閲覧専用で、パイオニアのKMZ形式データはG空間情報センター経由で有償（年額5.5万円）かつ再配布不可です。SNSや人流データも契約がないため使っていません。

## 4. 長期運用のための仕組み

このダッシュボードの元データは**時間が経つと取得できなくなります**。JARTICの5分値は過去1ヶ月分しか遡れず、通行規制は解除されるとポータルの一覧から消えます。そのため「取れるうちに取って残す」ことを設計の中心にしています。

### 交通量のアーカイブ

`fetch_and_prepare.py` が取得した生データを **追記専用（削除・上書きなし）** で蓄積します。

- `data/archive/traffic_raw.parquet` … 5分間値
- `data/archive/traffic_hourly.parquet` … 1時間値

実行のたびに、**アーカイブ済みのコマ（5分間値なら1コマ=5分）と期待されるコマの並びを突き合わせ、まだ持っていないコマだけ**をAPIに問い合わせます。1コマ=1リクエストなので範囲でまとめて取り直すより無駄がなく、途中に空いた穴も次の実行で埋まります。

`target.parquet` / `baseline.parquet` / `observations*.parquet` / `quake_info.json` はこのアーカイブから毎回再生成される「現在時点のビュー」なので、上書きされて構いません。

> **JARTIC側がそもそも配信していないコマ**（リクエストしても0件が返る）が時々あります。この場合はデータが存在しないため埋まらず、時系列図ではその区間だけ線が途切れます。

### 取得期間の考え方

- **開始**: 本震の前日から（`TARGET_START = 2026-07-27 03:00`）
- **終了**: 「本震発生時刻 + 2週間」まで**動的に伸びていきます**（`RECOVERY_PERIOD`）

被災後72時間はもちろん、交通が平常に戻っていく**復旧期の推移**まで追えるようにするためです。

### 通行規制のアーカイブ

`data/archive/regulations_archive.json` に **追記専用** で蓄積します（削除は一切しません）。

- 各規制は「**路線名・地域・区間の始終点座標・規制開始日時**」をキーに識別します。規制内容や終了日時は途中で変わるためキーに含めません
- `first_seen` / `last_seen`（初めて／最後に確認した日時）と `still_listed`（まだポータルに載っているか）を保持するので、**一覧から消えた後も「いつからいつまで、どういう規制だったか」を追えます**
- 規制内容や終了日時が変わったときだけ `history` に1行追記します（全面通行止め → 片側交互通行止め → 解除 といった推移が残ります）
- スナップ済みの経路はアーカイブから再利用するため、定期実行のたびに全件をOSRMの公開デモサーバーへ投げ直しません（1回あたり71リクエスト → 0リクエスト、実行時間40秒超 → 3秒）
- **ポータルからの取得に失敗した回は、アーカイブを一切変更しません**。取得できなかったことを「一覧から消えた」と誤判定しないためです

`data/regulations.json` は地図描画用の「現在のスナップショット」で、こちらは毎回上書きされます。

### 自動取得（GitHub Actions）

[`.github/workflows/fetch-and-archive.yml`](.github/workflows/fetch-and-archive.yml) が**6時間ごと**に `fetch_and_prepare.py` を実行し、`data/` 配下に変更があれば自動でコミット・pushします。手動で今すぐ実行したい場合は GitHub の Actions タブから `workflow_dispatch` で起動できます。

復旧期（本震から2週間）を過ぎるとフェッチ対象がなくなり実質no-opになりますが、ワークフロー自体は動き続けます。不要になったら Actions 設定からスケジュールを無効化してください。

> **タイムゾーンの注意**: CIランナーはUTCで動くため、日時の「いま」はすべてJSTに変換して扱っています（`_now_jst()`）。ここを素の `datetime.now()` にすると、対象期間の終端が9時間手前になり、本震後のデータを取り逃します。

## 5. 動かし方

### ダッシュボードを見るだけ

```bash
pip install -r requirements.txt
streamlit run app.py
```

`data/` 配下に前処理済みデータが同梱されているため、これだけで起動します。

### データを最新化する

```bash
pip install -r requirements.txt -r requirements-fetch.txt
python fetch_and_prepare.py
```

依存関係を2つに分けているのは、**`app.py` を geopandas なしで動かせるようにしている**からです（次節）。

## 6. 中身の構造

```
fetch_and_prepare.py   … オフラインのデータ取得・前処理（geopandas/shapely を使う唯一の場所）
  ├─ modules/api_request_func.py … JARTIC WFS APIリクエスト（範囲取得／コマ指定取得）
  ├─ modules/aggregation.py      … GeoJSON→GeoDataFrame変換、観測時刻のパース
  ├─ modules/earthquake_data.py  … 気象庁地震情報の取得・複数報の統合
  ├─ modules/anomaly.py          … 平常時ベースラインとのzスコア計算
  ├─ modules/holidays.py         … 内閣府の祝日CSV取得（平常時から祝日を除くため）
  ├─ modules/stations.py         … 常時観測点コードと緯度経度の対応（観測点マスタ）
  └─ modules/road_regulations.py … 「防災情報くまもと」の規制情報取得＋OSRM道路スナップ
       ↓ 追記（削除・上書きなし）
data/archive/*.parquet, data/archive/regulations_archive.json   … 恒久アーカイブ
       ↓ 切り出して生成（毎回上書き）
data/*.parquet, data/quake_info.json, data/regulations.json     … 現在時点のビュー
       ↓ 読み込みのみ
app.py                 … Streamlitダッシュボード（pandas/plotly/folium のみ）
```

**`app.py` は前処理済みデータを読み込むだけの薄いビュー層です。** これにより、GDALが使えない/使いにくい Streamlit Community Cloud のような環境でも動かせます。重い依存（geopandas/shapely/pyproj）は `fetch_and_prepare.py` の実行時（ローカルまたはGitHub Actions）にのみ必要です。

### 設定値の置き場所

対象エリア・期間・ベースライン期間は [`fetch_and_prepare.py`](fetch_and_prepare.py) の定数に固定値で書いてあります。**別の地震・地域で使う場合はここを書き換えてください。**

| 定数 | 意味 |
| --- | --- |
| `BBOX` | 対象エリア（現在は熊本県） |
| `MAINSHOCK_EID` | 本震の気象庁イベントID |
| `TARGET_START` | 分析対象期間の開始 |
| `RECOVERY_PERIOD` | 本震から何日後までを対象にするか（既定14日） |
| `BASELINE_WINDOWS` | 5分間値の平常時ウィンドウ |
| `HOURLY_BASELINE_WEEKS` | 1時間値の平常時を何週分さかのぼるか（既定8） |
| `MIN_AFTERSHOCK_INTENSITY` | 時系列図に印を付ける地震の最大震度のしきい値（既定 震度5弱） |

## 7. 注意点

- **これは研究・情報共有目的の簡易分析です。** 防災・避難行動の判断材料として公式に保証するものではありません
- 観測点は現在7点しかありません。エリア全体の交通行動を代表するものではなく、**その地点で何が起きたか**を見るものです
- 揺れの強さは震源距離で代理しており、実際の震度分布とは異なります
- 通行規制は熊本県が管理する道路のものが中心で、市町村道や高速道路の規制が網羅されているわけではありません
- 気象庁の地震情報は同一地震に対して複数の報（更新情報）が出ます。本ツールは報を統合して最新の非空値を採用していますが、**発表内容そのものが後から更新される**ことは前提にしてください
- 異常検知は「平常時からの統計的な外れ」を見ているだけで、**原因を特定するものではありません**。通行規制・迂回・自主的な外出抑制・観測機器の不調などが混ざります
