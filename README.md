# 熊本地震・交通量変化ダッシュボード (kumamoto-earthquake-traffic-map)

[![Open in Streamlit](https://static.streamlit.io/badges/streamlit_badge_black_white.svg)](https://kumamoto-earthquake-traffic-map.streamlit.app/)

**🔗 公開URL: https://kumamoto-earthquake-traffic-map.streamlit.app/**

2026年7月28日16:27頃に熊本地方で発生した地震（M7.1・最大震度7）の前後で、**交通量が平常時と比べてどう変わったか**を観測点ごとに可視化する簡易ダッシュボードです。

> **名称について**: 「行動変容」ではなく「交通量変化」としています。本ツールが持っているのは交通量と通行規制・地震情報だけで、迂回・外出抑制・通勤形態の変化といった**行動の中身やその要因を示すデータは収集していません**。平常時との差が出た理由は本ツールでは特定できません。そうしたデータを扱えるようになった時点で名称を見直します。

- 交通量データと地震情報を重ね合わせ、平常時との比較による**簡易異常検知**を行います
- 観測点をクリックして時系列を比較できるインタラクティブな地図を備えます（最大2地点を選択して比較可能）

## ねらい

災害直後の交通量の変化を、**公開データだけで・発災当日から・後から検証できる形で**残すことを目的にしています。

- **公開データのみ**: 認証やAPIキー、有償契約を必要としないデータだけで構成しています。誰でも同じ手順で再現・検証できることを優先しました
- **取れるうちに残す**: JARTICの5分値は過去1ヶ月分しか遡れず、通行規制は解除されるとポータルの一覧から消えます。そのため取得した生データを**追記専用でアーカイブ**し、後から遡って分析できるようにしています（[データのアーカイブについて](#データのアーカイブについて)）
- **判断の根拠を明示する**: 「平常時」の定義や異常判定のしきい値、代替指標を使っている箇所を README とダッシュボード上の両方に書いています。数字だけを見せて解釈を委ねる状態にしないことを意図しています
- **復旧期まで追う**: 発災直後だけでなく、交通が平常に戻っていく過程まで対象期間に含めています

## できること

| タブ | 内容 |
| --- | --- |
| 地図・時系列 | 観測点別の異常度（zスコア）と通行規制情報を地図上に重ね合わせ、選択した観測点（最大2地点）の時系列（平常時 vs 観測実績）を並べて表示。粒度（5分間値／1時間値）と車種別表示の切り替えができます |
| 異常検知一覧 | 地震発生後に検知された異常のテーブルとCSVダウンロード |
| データダウンロード | 5つのデータセット（交通量の5分値・1時間値、通行規制の一覧・状態変化履歴、異常検知の入力データ）を**内容・行数・期間・対応する列定義書のシート名を並べた一覧表**から選んでCSVで取得。各列の意味・単位をまとめた**列定義書**をExcel（1シート＝1データセット）でダウンロードできます（実データの列と自動照合し、食い違いがあるときだけ理由付きの備考を表示します） |

観測点は**地図上の丸いマーカーをクリック**するか、**画面上部のプルダウンから選択**するかのどちらでも選べます。規制の描き分けは**色＝規制の区分**（今回の地震以降に始まった全面通行止め／同じく片側交互など／地震前からの規制）、**線の形＝いま規制中か解除済みか**（実線／破線）の2軸で、この2つは独立しています。破線が解除済みを表すのは色にも道路の種別にもよらず共通で、県のフィードにある県道以下の規制でも、別レイヤの直轄国道でも同じです。凡例は地図の上部に置いています。

### 通行規制データに載らない規制がある

交通量が0になっていても、その原因となる規制が地図に出てこないことがあります。理由は2つあります。

**① 管理者の違い（構造的な欠落）**

「防災情報くまもと」の通行規制情報は**県・市町村が管理する道路**が対象です。実際に含まれている国道は補助国道（218/219/265/266/442/443/445号）だけで、**国が管理する直轄国道（国道57号・3号など）の規制は最初から載りません**。

実例として、**国道57号 北側復旧道路（阿蘇西IC〜大津IC）は本震と同時（2026-07-28 16:27）に全面通行止め**となり、うち車帰IC〜大津IC が翌 **02:00 に解除**されました（熊本河川国道事務所 道第1〜3報）。この区間には常時観測点 `9310127` があり、地震直前は5分あたり約81台だった交通量が0になっています。**02:00 に交通量が再開しており、公表された解除時刻と一致します。**

これらの規制はポータルのデータに存在しないため、PDFから転記して `data/mlit_regulations.json` に持ち、ダッシュボードでは次のように扱っています。

- PDFは区間を「○○IC〜○○IC」と名前で示すだけで座標がありませんが、実在する道路区間なので**端点のICの座標から線形を復元**して別レイヤに描いています。端点は OpenStreetMap の `highway=motorway_junction` ノード（ノードIDを固定値で保持）、その間を OSRM でルーティングして道路網に沿った線にしています（[`scripts/build_mlit_paths.py`](scripts/build_mlit_paths.py)）。復元した延長はPDF記載の延長と並べて記録しており、ダッシュボード上でも確認できます
- キロポストで示された地点（`216K600` など）のように線形を作れないものは、掛かっていた観測点が分かる場合だけその**すぐ上**に **▲** を置きます（観測点の丸とは重ならない高さ。現在は該当なし）
- 該当観測点を選んだとき、**時系列図に通行止め期間の帯**を表示します
- 地図の下に出典PDFへのリンク付きで一覧を出します

現在転記済みの規制（2026-07-29 22時時点で公表されていた12件のPDFをすべて転記。road4 は欠番）:

| --- | --- | --- | --- | --- | --- |
| 九州中央自動車道 | 小池高山IC〜山都通潤橋IC（PDF 約23km / 復元 23.51km） | 全面通行止め | 07-28 16:27 〜 07-29 03:00 | 線 | なし（路線上に観測点なし） |

復元した延長がPDF記載と一致しないのは**測り方の違い**です（ランプを含むか、キロポスト基準かなど）。九州中央自動車道は +0.51km で概ね一致しますが、北側復旧道路の車帰IC〜大津ICは −1.41km あります。線形は「どの区間が止まっていたか」を示すためのもので、延長の正確な再現を意図したものではありません。両方の値をJSONと画面に残しています。

なお `9310127` には、**上記の規制では説明できない2回目のゼロ期間**があります。道第4報では 2026-07-29 08:00 に北側復旧道路の全区間が解除されていますが、交通量は同日 07:35 以降ほぼ0のまま（21:40までの約14時間で計10台）で、欠測ではなく実測の0です。原因は特定できていません（公表済みの報にこれを説明するものはありません）。**時系列図の帯は 16:27〜02:00 の通行止めのみを示すもので、その後のゼロ期間の原因を示すものではありません。**

**観測点との対応づけは推測で行っていません。** ダッシュボードはこの対応づけをもとに地図へ ▲ を置き時系列図に規制期間の帯を描くため、誤ると「規制のせいで交通量が落ちた」という誤った読み方を誘発します。裏付けが取れなかったものは対応づけせず、その理由を画面にそのまま出しています（例: 国道3号の最も近い観測点 `9110040` は規制開始より前から交通量がほぼ0で、規制中に回復しているため、この通行止めでは説明できない）。

### 規制を追加するとき

新しい報が出たら、PDFを `data/qsr_regulations/` に置き、本文を確認して `data/mlit_regulations.json` の `items` に追記します。本文の確認には補助スクリプトを使えます（`pymupdf` が必要です。ダッシュボードの動作には不要）。

```bash
pip install pymupdf
python scripts/dump_qsr_pdf_text.py            # data/qsr_regulations/*.pdf 全部
python scripts/dump_qsr_pdf_text.py road2-4    # ファイル名で絞り込み
```

追記する項目の形式と注意点はスクリプトの docstring にまとめています。観測点がどの路線上にあるかは OSRM の nearest で確認できます。

```bash
curl -s "https://router.project-osrm.org/nearest/v1/driving/130.97624,32.91327?number=3"
```

区間の線形を作るには、端点のICを [`scripts/build_mlit_paths.py`](scripts/build_mlit_paths.py) の `IC_NODES` / `SECTION_ENDPOINTS` に追加して実行します。ICの座標は Overpass API で探せます（ノードIDを固定値で持たせ、実行ごとに結果が揺れないようにしています）。

```bash
python scripts/build_mlit_paths.py --dry-run   # 延長の差を確認
python scripts/build_mlit_paths.py             # data/mlit_regulations.json に書き込む
```

**② 収集開始が本震より後（時間的な欠落）**

規制情報の収集を始めたのが本震の翌日であるため、県管理道路であっても**それ以前に解除された規制は残っていません**。アーカイブに記録が残っている最も古い時点はダッシュボード上に表示しています。

## 手法・注意点

- **平常時（ベースライン）**: **日区分ごとに別々**の1時間交通量です。曜日で交通量の形がまったく違うため、実測の各行は**自分と同じ日区分**の平常時と比べます。観測点×日区分×時刻(hour)ごとに平均・標準偏差を求めます。5分間値は過去1ヶ月しか遡れないのに対し1時間値は3ヶ月遡れるため、母集団を広く取れる1時間値を採用しています。1日の区切りは深夜帯を日付でまたいで切らないよう**03:00起点**にしており、日区分の判定もこの区切りで行います

| 日区分 | 定義 | 母集団 |
| --- | --- | --- |
| 月・火・水・木・金 | その曜日で祝日でない日 | 各曜日8日分（新しい順に遡る） |
| 土 | 土曜で祝日でない日 | 8日分 |
| 日祝 | 日曜、または平日・土曜にあたる祝日 | 8日分 |

  祝日の扱いは[内閣府の祝日CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)で判定します。**祝日は曜日によらず「日祝」に入れます**（日曜はもともと休日なので祝日と重なっても傾向が変わらず、平日・土曜の祝日は日曜寄りの交通になるため）。祝日で除外された曜日は、8日を確保するためさらに前の週へ遡ります（例: 2026-07-20 海の日（月）は月曜の母集団から外れ、日祝に入り、月曜は5/25まで遡って8日を確保）。使った日は実行ログと `quake_info.json` の `hourly_baseline_daytypes` に残ります

  **なぜ曜日を分けるか（実測）**: 火曜だけの平常時で評価すると、地震と無関係な平常時の土日でも**8割の行が異常判定**になりました（朝7時は火曜比0.68倍、深夜22時は1.99倍）。日区分別にしたうえで、母集団に入っていない土日（5/30・5/31）で検証すると誤検知は**71% → 12%**に下がりました
- **異常検知**: 1時間値どうしの比較で定義します。1時間値の実績と、**同じ日区分**の平常時の平均・標準偏差から `|zスコア| >= 2` を異常としてフラグ。**地図の色分けと異常検知一覧もこの1時間値ベースの判定に基づきます**
- **時系列の4ビュー**: 実績の既定は5分間値です
  - `5分間値`: 実績は5分間値。平常時は1時間値ベースなので単位を合わせるため1/12しています。**この帯は「平常時の1時間あたり交通量の日々のばらつき÷12」であり、5分間値そのもののばらつきではないため狭く出ます**（同梱データ時点では、5分間値どうしで求めたσの平均 8.2 に対して 3.0 程度）。細かい変動を追うのには使えますが、帯からの外れ具合を異常の根拠にはしないでください
  - `1時間値`: 実績・平常時とも1時間値どうしの比較。異常検知の判定もこの粒度です
  - `車種別・5分間値` / `車種別・1時間値`: 上り・下りの図はそのままに、**同じ図の中で小型車（濃い色）と大型車（明るい色）を分けて**表示します。選択1地点目は 赤＝小型／ピンク＝大型、2地点目は 緑＝小型／ライムグリーン＝大型。大型車は小型車の1割程度の水準なので、同じ縦軸でも下側に分かれて描かれます。線種で分ける案（大型を破線）は**平常時の点線と紛らわしい**ため採っていません。異常検知の判定は車種を合計した1時間値で行っており、この図で判定は変わりません。**5分間値のほうは大型車が5分あたり中央値4台（0台が14%）と粒度が粗く**線がぎざぎざになるため、水準の比較には1時間値のほうが向きます。平常時の帯は1時間値σの1/12なので、台数の小さい大型車では実際のばらつきより狭く出る影響がより大きくなります

  **車種別で見える差（日区分・時刻をそろえた実測）**: 地震後、小型車は平常時の **92.6%**（−7.4%）まで下がったままなのに対し、大型車は **103.4%**（+3.4%）と平常時を上回って推移しています。合計交通量だけを見ると打ち消し合って見えません。なお API は車種判別不能の台数も返しますが、アーカイブ全期間で**1台**しかないため系列としては扱っていません
- **観測点のID**: JARTICの「常時観測点コード」（例 `9110030`）を観測点の識別子として使い、地図・セレクタ・グラフ凡例・CSVで共通にしています。アーカイブにはこの列を持たない時期のデータも含まれるため、`data/stations.json`（コードと緯度経度の対応表）を経由して後から付け直しています（座標はAPIの応答で末尾の桁がわずかに揺れるため、5桁≒1mに丸めて突き合わせ）
- **地震前からの規制を分けて表示**: 2020年7月豪雨による通行止めのように数年前から継続している規制が一覧に含まれるため、規制開始日時が本震以降かどうかで分類し、地図では別レイヤ・別の色にしています。これをしないと今回の地震によるものと見分けられません
- **地震後が欠測の観測点**: 地震発生と同時に配信が止まった観測点があります（`9310035`：1時間値は 2026-07-28 15:00 が最後）。この場合zスコアが定義できないため、地図では**灰色・破線の丸**で「異常なし」とは区別して表示し、ツールチップに最後に値があった時刻を出します。異常度の色分けからは外れますが、**配信が止まったこと自体が情報**なので地図から消さないようにしています
- **異常検知は原因を特定するものではありません**: 「平常時からの統計的な外れ」を見ているだけで、通行規制・迂回・自主的な外出抑制・観測機器の不調などが混ざります
- 観測点は現在9点です。エリア全体の交通を代表するものではなく、その地点で何が起きたかを見るものです
- 1時間値のアーカイブには、**2026-07-01 までしか配信されていない観測点（`9310183`）が1点含まれます**。分析対象期間（本震前日以降）にデータがないため、地図・時系列・異常検知には登場しませんが、ダウンロードできる1時間値CSVには残しています（取得できたものを消さない方針のため）
- 対象エリア・期間・ベースライン期間は [`fetch_and_prepare.py`](fetch_and_prepare.py) の定数で固定値になっています。別の地震・地域で使う場合はここを書き換えてください

| 定数 | 意味 |
| --- | --- |
| `BBOX` | 対象エリア（現在は熊本県） |
| `MAINSHOCK_EID` | 本震の気象庁イベントID |
| `TARGET_START` | 分析対象期間の開始 |
| `RECOVERY_PERIOD` | 本震から何日後までを対象にするか（既定14日） |
| `BASELINE_WINDOWS` | 5分間値の平常時ウィンドウ |
| `HOURLY_BASELINE_DAYS_PER_TYPE` | 1時間値の平常時を日区分ごとに何日集めるか（既定8） |
| `MIN_AFTERSHOCK_INTENSITY` | 時系列図に印を付ける地震の最大震度のしきい値（既定 震度5弱） |

- **動的取得期間**: 対象期間の終端は「本震発生時刻 + `RECOVERY_PERIOD`（既定2週間）」まで動的に伸びていきます。被災後72時間はもちろん、交通が平常に戻っていく復旧期の推移まで追えるようにするためです

## データのアーカイブについて

JARTIC交通量オープンデータの5分値は**過去1ヶ月分しか遡って取得できません**（[公式サイト](https://www.jartic-open-traffic.org/)）。この制約に対応するため、`fetch_and_prepare.py` は取得した生データを `data/archive/traffic_raw.parquet` に**追記専用（削除・上書きなし）**で蓄積します。

- `target.parquet`/`baseline.parquet`/`observations*.parquet`/`quake_info.json` はこのアーカイブから毎回再生成される「現在時点のビュー」で、上書きされて構いません
- 実行のたびに、アーカイブ済みの**コマ（5分間値なら1コマ=5分）と期待されるコマの並びを突き合わせ、まだ持っていないコマだけ**をAPIに問い合わせます。1コマ=1リクエストなので範囲でまとめて取り直すより無駄がなく、途中に空いた穴も次の実行で埋まります
- **JARTIC側がそもそも配信していないコマ**（リクエストしても0件が返る）が時々あります。この場合はデータが存在しないので埋まらず、時系列図ではその区間だけ線が途切れます
- GitHub Actions（後述）で定期実行することで、復旧期（本震+2週間）が終わるまで自動的にアーカイブが育っていきます
- 1時間値も同様に `data/archive/traffic_hourly.parquet` に蓄積します（1時間値は3ヶ月遡れる）

### 通行規制情報のアーカイブ

通行規制も**解除されるとポータルの一覧から消えて、後から取得できません**。そのため `data/archive/regulations_archive.json` に**追記専用**で蓄積します（削除は一切しません）。

- 各規制は「路線名・地域・区間の始終点座標・規制開始日時」をキーに識別します（規制内容や終了日時は途中で変わるためキーに含めません）
- `first_seen` / `last_seen`（初めて／最後に確認した日時）と `still_listed`（まだポータルに載っているか）を保持するので、一覧から消えた後も「いつからいつまで、どういう規制だったか」を追えます
- 規制内容や終了日時が変わったときだけ `history` に1行追記します（全面通行止め → 片側交互通行止め → 解除 といった推移が残ります）
- スナップ済みの経路はアーカイブから再利用するため、定期実行のたびに全件をOSRMの公開デモサーバーへ投げ直しません
- ポータルからの取得に失敗した回は、**アーカイブを一切変更しません**（取得できなかったことを「一覧から消えた」と誤判定しないため）
- `data/regulations.json` は地図描画用の「現在のスナップショット」で、こちらは毎回上書きされます

### 自動取得（GitHub Actions）

[`.github/workflows/fetch-and-archive.yml`](.github/workflows/fetch-and-archive.yml) が6時間ごとに `fetch_and_prepare.py` を実行し、`data/` 配下に変更があれば自動でコミット・pushします。手動で今すぐ実行したい場合は GitHub の Actions タブから `workflow_dispatch` で起動できます。

復旧期（本震から2週間）を過ぎるとフェッチ対象がなくなり実質no-opになりますが、ワークフロー自体は動き続けます。不要になったら GitHub の Actions 設定からスケジュールを無効化してください。

> CIランナーはUTCで動くため、日時の「いま」はすべてJSTに変換して扱っています（`_now_jst()`）。素の `datetime.now()` にすると対象期間の終端が9時間手前になり、本震後のデータを取り逃します。

## アーキテクチャ

```
fetch_and_prepare.py   … オフラインのデータ取得・前処理（geopandas/shapely使用）
  ├─ modules/api_request_func.py … JARTIC WFS APIリクエスト（範囲取得／コマ指定取得）
  ├─ modules/aggregation.py      … GeoJSON→GeoDataFrame変換、観測時刻のパース
  ├─ modules/earthquake_data.py  … 気象庁地震情報の取得・複数報の統合
  ├─ modules/anomaly.py          … 平常時ベースラインとのzスコア計算
  ├─ modules/holidays.py         … 内閣府の祝日CSV取得（平常時から祝日を除くため）
  ├─ modules/stations.py         … 常時観測点コードと緯度経度の対応（観測点マスタ）
  └─ modules/road_regulations.py … 「防災情報くまもと」の通行規制情報取得＋OSRM道路スナップ
       ↓ 追記
data/archive/traffic_raw.parquet  … 恒久アーカイブ（削除・上書きなし）
       ↓ 切り出して生成
data/*.parquet, data/quake_info.json  … 前処理済みの軽量データ（現在時点のビュー）
       ↓ 読み込みのみ
app.py                  … Streamlitダッシュボード（GDAL依存なし、pandas/plotly/foliumのみ）
```

`app.py` は前処理済みデータを読み込むだけの薄いビュー層です。これにより、Streamlit Community Cloud等のGDALが使えない/使いにくい環境でも動かせるようにしています。重い依存（geopandas/shapely/pyproj）は `fetch_and_prepare.py` の実行時（ローカルまたはGitHub Actions）にのみ必要です。

## セットアップ

### 1. ダッシュボードを見るだけの場合

```bash
pip install -r requirements.txt
streamlit run app.py
```

`data/` 配下に本リポジトリ同梱の前処理済みデータが入っているため、これだけで起動できます。

### 2. データを最新化する場合

```bash
pip install -r requirements.txt -r requirements-fetch.txt
python fetch_and_prepare.py
```
