# モバイル空間統計（500mメッシュ人口）の扱い

ダッシュボードの「人口推計値×交通量」タブで使っているデータについてまとめています。交通量・通行規制と違い、**このデータだけは元データも集計結果も公開リポジトリに入れていません**。

## 何を使っているか

| | |
| --- | --- |
| 提供元 | モバイル空間統計®（NTTドコモ／ドコモ・インサイトマーケティング）リアルタイム国内人口分布 |
| 粒度 | 500mメッシュ・1時間・人口推計値（総数と居住地別） |
| 期間 | 2026-07-21 00:00 〜 2026-08-03 23:00（336時点） |
| 範囲 | 熊本県内（500mメッシュの中心が県域に入るもの）26,798メッシュ |
| 秘匿 | 10人未満のメッシュは配信されない |

配布物のうち使っているのは**総数**（`01_total` / `*_00000`）と**居住地市区町村別**（`04_residence_city` / `*_00003`）です。居住地別は「**そのメッシュのある市区町村の居住者か・それ以外（来訪者）か**」の2区分に畳んでから集計し、居住地の市区町村コードは残していません。**性年代別（`*_00001`）と居住地都道府県別（`*_00002`）は読み込んでいません。**

期間が交通量（本震の2週間前から本震の3週間後まで）より短いのは、提供されているのが過去一括分（07-21〜07-28）と自動連係分（07-29以降）に限られるためです。

## 公開リポジトリに置かないこと

提供データそのものの第三者提供に当たるため、次の2つを分けて扱っています。

1. **元データ**（`data/mss/`）と**中間物**（`data/mss_build/`）は `.gitignore` に入れ、リポジトリに登録しない
2. アプリが読むのは、公開してよい粒度まで落とした集計ファイルだけ。それも非公開の置き場に置き、実行時に取得する

集計ファイルは3つです。

| ファイル | 中身 | 大きさ |
| --- | --- | --- |
| `mesh_population.parquet` | メッシュ × 時点の人口推計値（3,901,597行）。総数と居住者・来訪者の内訳 | 14.4 MB |
| `mesh_population_summary.parquet` | メッシュごとの位置・市区町村名・発災前後の平均（26,798行・88列） | 5.2 MB |
| `mesh_population_meta.json` | 期間・件数・出典・秘匿の扱い | 数KB |
| `mesh_population_summary.gpkg` | 上に500mメッシュのポリゴンを付けたもの（**QGIS向け**・EPSG:4326） | 16.1 MB |
| `mesh_population_summary.geojson` | 同じ内容のGeoJSON版。どこでも開ける代わりに大きい | 62.5 MB |

**ポリゴンはメッシュコードから作っています**（アプリの地図と同じ計算）。角は7桁に丸めてあるので、隣り合うメッシュの辺はぴったり接します。実測で、26,798件すべてが別の位置にあり、重なりは0km²、1メッシュの面積は0.270〜0.273km²です（緯度1/240度＝約463m、経度1/160度＝この緯度で約585m）。

アプリが読むのは前の3つで、後ろの2つは**手元のGISで分析するためのもの**です（アプリからは読みません）。地図に描いているのと同じ中身で、こちらは全26,798メッシュが入ります（アプリが描くのは全時点で配信された3,834メッシュだけなので、`n_hours == 336` で絞ると同じになります）。列の説明は非公開リポジトリの `README.md` に置いています。

置き場は**非公開のGitHubリポジトリ** `centrixuge/kumamoto-mesh-population-data`（private）で、この3ファイルだけを置いています。アプリはGitHubのcontents APIで実行時に読みます（[`modules/mesh_population.py`](../modules/mesh_population.py)）。手元に `data/mss_build/` があるときはそちらが優先されるので、開発中は設定なしで動きます。

Streamlit Cloud側の設定（公開アプリとdevelop確認用アプリの両方に必要）:

```toml
[mesh_population]
repo  = "centrixuge/kumamoto-mesh-population-data"
ref   = "main"
token = "github_pat_..."
```

トークンは **fine-grained PAT** を使います（[設定ページ](https://github.com/settings/personal-access-tokens/new)）。

- Resource owner: `centrixuge` / Repository access: **Only select repositories** → `kumamoto-mesh-population-data`
- Repository permissions: **Contents: Read-only** のみ（他は付けない）

設定が無い場合、このタブは「集計データが見つかりません」と出るだけで、ほかのタブは通常どおり動きます。

新しい時点のデータを足したときは、`scripts/build_mesh_population.py` を回し直して、出力3ファイルを非公開リポジトリに push すれば反映されます（アプリ側のキャッシュは1時間）。

**画面に出した値そのものは、ブラウザ側から取り出せます。** グラフの系列も地図のメッシュ属性もクライアントに渡るためで、ダウンロードボタンを付けないことは一括配布をしないという意味しかありません。公開してよい粒度に落としたものだけを置く、という上の2番目がここでの実質的な担保です。

## 集計のしかた

```bash
python scripts/build_mesh_population.py
```

- **熊本県内の判定**: 500mメッシュの中心が国土数値情報 行政区域（N03-20240101_43）の熊本県ポリゴンに入るかどうか。スクリプトが初回に配布元からダウンロードします
- **メッシュの緯度経度**: メッシュコード（9桁）から計算しています。1〜4桁目が1次メッシュ、5・6桁目が2次、7・8桁目が3次（1km）、9桁目がその4分割（1:南西 2:南東 3:北西 4:北東）。**メッシュのシェープファイルは要りません**
- **市区町村名**: N03の市区町村ポリゴンとの重ね合わせ。熊本市の区名はこの年次のN03の名称欄に入らないため、行政区域コード（43101〜43105）から補っています

発災前の平均を全メッシュで合計すると約162万人になります。10人未満のメッシュが配信されない分だけ県全体の人口より小さくなりますが、桁は合っています。

## 条件違いで並べる（「人口推計値の時点比較」タブ）

同じ集計を左右2枚で見比べるタブです。左右それぞれに「出す値（増減率／人口・発災前／人口・発災後）×時間帯×日区分」を持たせてあるので、**発災前と発災後**、**夜間と昼間**、**平日と休日**のどの組み合わせでも並べられます。既定は左が発災前の人口、右が発災前後の増減率（どちらも夜間・平日）です。どこに人がいた場所で、どれだけ動いたかが1画面で読めます。

- 2枚は folium の `DualMap` で、**拡大・移動が連動**します。見比べる図で縮尺がずれると意味がないためです
- **メッシュにカーソルを合わせると、同じメッシュが反対側でも枠で囲まれます**（メッシュコードで対応づけ）。片方で見ている場所が反対側のどこなのか分からないと比べられないためです
- 描いているメッシュは左右同じ（全336時点で配信された3,834メッシュ）で、色の区切りも共通なので、**左右で同じ色は同じ値**を指します
- **このタブにはクリックでの選択を置いていません。** st_folium の返り値からはどちらの地図を押したのかが分からず、取り違えるためです。選択と時系列変化は「人口推計値×交通量」タブにあります
- メッシュを2枚ぶん描くのでHTMLは3.3MBほどになります（1枚のタブは1.6MB）

初めて開いたときは、メッシュ 483075254（宇城市）と観測点 9110040 を選んだ状態で出します（何も選ばれていない図だと、この画面で何が見られるのか伝わらないため）。

## 地図と時系列の読み方

- **色**は既定では発災後（本震以降）と発災前の平均人口の比。減った側が青、増えた側が赤で、**区切りは15%・30%**です（対象の日数が少なく比がよく振れるので、10%・25%で切ると大半が「動いた」区分に入り、地図から差が読めませんでした）。**「地図に出す値」で人口そのもの（発災後／発災前）に切り替えられます** — 多いほど濃い1色系で、区切りは100・250・500・1,000人（地図に出す3,834メッシュの中央値132人、上位1割が826人以上という実測から）。増減率だけだと、元から人が少ない場所の1〜2割の増減が都心部と同じ色になるためです。**時間帯（全時間帯／夜間＝3時／昼間＝14時）と日区分（平日／休日＝土日祝）の組み合わせ**で選べます（既定は夜間・平日）。平日と休日をまとめた「全日」は出していません。その比は日区分の違いが混ざるだけで、読んでも意味がないためです。夜間・昼間の代表時刻はどちらも移動の途中が混じりにくい時刻で、3時は就寝中、14時は通勤通学が済んだ後です。**「夜間人口」「昼間人口」とは呼びません** — あちらは常住地・従業地で数える別の定義で、ここで見ているのはその時刻にそこに居た人数です
- **居住地**（すべて／居住者＝当該市区町村／来訪者＝それ以外）も選べます。居住者が減って来訪者が増えていれば、避難や支援で人が入れ替わったことが読めます。判定は配布データの居住地コード（5桁）と、メッシュのある市区町村の行政区域コードの一致で、熊本市は区単位（43101〜43105）まで区別されます。**「すべて」は総数の配信なので、居住者＋来訪者とは一致しません** — 居住地ごとに10人未満だと配信されないため、内訳の合計のほうが小さくなります（全期間で総数の88.1%）
- 実測すると、地図に出す3,834メッシュの合計で、夜間3時・平日は居住者101.6万人 vs 来訪者11.7万人、昼間14時・平日は居住者73.7万人 vs 来訪者31.1万人でした（発災前）。夜はほぼ居住者、昼は来訪者が3割という形です
- **日区分を分けるのは、平日と休日で人の居場所が元から違うためです。** 「平日」は発災前の平日平均と発災後の平日を、「休日」は休日どうしを比べます。ただし**発災前は平日6日・休日2日、発災後は平日5日・休日2日しかありません**（収録が07-21〜08-03のため）。とくに休日は2日どうしの比なので、1日の事情がそのまま比に出ます
- 集計側は `pre_{母集団}_{日区分}_{時間帯}` / `post_…` / `ratio_…` の形で列を持っています（母集団 all・rs・vi、日区分 wd・hd、時間帯 all・h3・h14。集計には全日 all も残していますが画面には出しません）。**集計を作り直して置き場に上げたときは、動いているアプリが古い集計を掴んだままになることがあります**（1時間キャッシュ）。列が足りなければ一度だけ取り直すようにしてあり、それでも足りなければその旨を画面に出します
- **メッシュ（1つ）と常時観測点（1点）を同じ地図から選び、1つの図に重ねられます**。以前はメッシュを2つ選べましたが、居住地の内訳（3段）と交通量まで重なるとどの棒がどれか追えないため、1つに絞りました。単位が違うので縦軸を分け、**左が人口推計値（人・棒）、右が交通量（台/時・上下計・線）です**。人口はその時刻にそこに居た人数なので棒、交通量は流れなので線にしています。**棒は居住地で塗り分け**（濃い＝居住者、薄い＝来訪者、いちばん薄い＝居住地別が10人未満で配信されなかった分）、3つを積むと総数になります。棒は青緑（居住者 #26A69A・来訪者 #9CD8D0・内訳なし #E0F2F0）で、平常時の階段線は濃い青緑 #00695C、交通量は朱色 #DE3F1B です（青緑の棒の上でも沈まない色。地図の色分けとは無関係になったので、図の中での見やすさだけで選んでいます）。平常時の階段線は、棒が時刻を中心に置かれるのに合わせて30分手前から引いています（そのままだと段が半コマ右へずれます）。系列名は短くし、どのメッシュ・どの観測点かは図の見出しに出しています（名前に入れると凡例が変なところで折り返します）。平常時は、人口が棒と同じ刻みの階段線、交通量が点線です。図の高さは500pxです（交通量は夜間にほぼ0まで落ちるので、縦に伸ばすと棒の側が読みにくくなります）
- **区分の選択と「クリックで選ぶもの」は地図の真上**に置いています（画面の幅が狭いと、上に離して置いた操作は地図と時系列図を並べたまま切り替えられないため）。**クリックで選ぶものは「メッシュ／観測点」の切り替え式**です。観測点はメッシュの上に乗るので、両方を同時に押せる状態だとメッシュを狙っても観測点が拾ってしまいます。選んでいないほうは当たり判定から外し（Leafletの `interactive: false`）、カーソルを合わせても何も出ないようにしています。地図は500mメッシュが押しやすいよう、他の地図より1段階寄せた縮尺から始めます
- **観測点の形（●＝一般国道／■＝高速自動車国道）と、その凡例は交通量のタブと共通です。** 凡例は地図の中（右上）に固定で出します（以前はこの地図に凡例を出しておらず、また高速の点が無いと凡例そのものが消える条件も入っていました）。凡例の印はこの地図の観測点と同じ白塗りにしています（交通量のタブは異常度で塗るので、そちらの凡例は塗りつきです）
- この地図の**観測点は白い印**で、異常度による色や大きさの描き分けはしていません（メッシュの色と選択枠が読めなくなるため）。異常度で描き分けた地図は交通量のタブにあります。**選んでいるものは、白い縁取りの上に図と同じ色の枠**で示します（メッシュは青緑 #00695C、観測点は朱色 #DE3F1B。塗りはどちらも変えません）。白い縁取りは、下の塗り（青〜赤／黄〜青）に関係なく輪郭が見えるようにするためのもので、当たり判定からは外してあります（上の線でクリックを拾います）
- 交通量は人口に合わせて**1時間値の上下計**を使います。表示期間は交通量の図と同じ左端（本震の前日 07-27 12:00）から、モバイル空間統計の収録の終わり（08-03 23:00）までです。人口はこれより前、交通量はこれより後までデータがありますが、重ねて読む図なので両方が揃っている範囲に合わせています
- メッシュ・観測点をどちらも1つに絞っているのは、居住地の内訳（3段）＋平常時＋交通量（実績・平常時）で6系列になるためです。これ以上増やすとどれがどれか追えなくなります
- **地図に出すメッシュは「全336時点で配信されたもの」（3,834メッシュ）に固定**しています。10人未満は配信されないので、時間帯によって出たり消えたりするメッシュを混ぜると比が同じ土台で比べられません。全26,798メッシュを描くとGeoJSONが8MBを超えてブラウザが重くなる、という理由もあります
- **平常時**は、発災前（07-21 00:00〜本震）の同じ日区分（平日／土／日祝）・同じ時刻の平均。**発災前は8日分しかないため、土・日祝はそれぞれ1日分の値です**（平日は6日分）。交通量側の平常時は2週間分から取っているので、同じ「平常時」でも厚みが違います
- **線が切れている**ところは、その時間帯に10人未満で配信されなかったことを示します。0人ではありません

## 分かっていないこと

- 提供データは推計値で、ドコモの契約者数から人口全体に拡大したものです。拡大の方法は提供元の公開情報の範囲でしか分かりません
- 500mメッシュの帰属は在圏の基地局情報に基づくため、メッシュ境界付近の帰属には誤差があります
- 避難所の滞在人数のような、施設単位の値は出せません（メッシュ内の合計しか分かりません）
