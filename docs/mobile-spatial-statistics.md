# モバイル空間統計（500mメッシュ人口）の扱い

ダッシュボードの「地図・人口の時系列変化」タブで使っているデータについてまとめています。交通量・通行規制と違い、**このデータだけは元データも集計結果も公開リポジトリに入れていません**。

## 何を使っているか

| | |
| --- | --- |
| 提供元 | モバイル空間統計®（NTTドコモ／ドコモ・インサイトマーケティング）リアルタイム国内人口分布 |
| 粒度 | 500mメッシュ・1時間・人口推計値（総数） |
| 期間 | 2026-07-21 00:00 〜 2026-08-03 23:00（336時点） |
| 範囲 | 熊本県内（500mメッシュの中心が県域に入るもの）26,798メッシュ |
| 秘匿 | 10人未満のメッシュは配信されない |

配布物には性年代別・居住地都道府県別・居住地市区町村別も含まれますが、**総数以外は集計にも読み込んでいません**。

期間が交通量（本震の2週間前から本震の3週間後まで）より短いのは、提供されているのが過去一括分（07-21〜07-28）と自動連係分（07-29以降）に限られるためです。

## 公開リポジトリに置かないこと

提供データそのものの第三者提供に当たるため、次の2つを分けて扱っています。

1. **元データ**（`data/mss/`）と**中間物**（`data/mss_build/`）は `.gitignore` に入れ、リポジトリに登録しない
2. アプリが読むのは、公開してよい粒度まで落とした集計ファイルだけ。それも非公開の置き場に置き、実行時に取得する

集計ファイルは3つです。

| ファイル | 中身 | 大きさ |
| --- | --- | --- |
| `mesh_population.parquet` | メッシュ × 時点の人口推計値（3,901,597行） | 8.0 MB |
| `mesh_population_summary.parquet` | メッシュごとの位置・市区町村名・発災前後の平均 | 1.0 MB |
| `mesh_population_meta.json` | 期間・件数・出典・秘匿の扱い | 数KB |

置き場は**非公開のGitHubリポジトリ** `centrixuge/kumamoto-mesh-population-data`（private）で、この3ファイルだけを置いています。アプリはGitHubのcontents APIで実行時に読みます（[`modules/mesh_population.py`](../modules/mesh_population.py)）。手元に `data/mss_build/` があるときはそちらが優先されるので、開発中は設定なしで動きます。

Streamlit Cloud側の設定（公開アプリとdevelop確認用アプリの両方に必要）:

```toml
[mesh_population]
repo  = "centrixuge/kumamoto-mesh-population-data"
ref   = "main"
token = "github_pat_..."
```

トークンは **fine-grained PAT** を使います（[設定ページ](https://github.com/settings/personal-access-tokens/new)）。

- Resource owner: `centrixuge` / Repository access: **Only select repositories** → `kumamoto-mesh-population-data`
- Repository permissions: **Contents: Read-only** のみ（他は付けない）

設定が無い場合、このタブは「集計データが見つかりません」と出るだけで、ほかのタブは通常どおり動きます。

新しい時点のデータを足したときは、`scripts/build_mesh_population.py` を回し直して、出力3ファイルを非公開リポジトリに push すれば反映されます（アプリ側のキャッシュは1時間）。

**画面に出した値そのものは、ブラウザ側から取り出せます。** グラフの系列も地図のメッシュ属性もクライアントに渡るためで、ダウンロードボタンを付けないことは一括配布をしないという意味しかありません。公開してよい粒度に落としたものだけを置く、という上の2番目がここでの実質的な担保です。

## 集計のしかた

```bash
python scripts/build_mesh_population.py
```

- **熊本県内の判定**: 500mメッシュの中心が国土数値情報 行政区域（N03-20240101_43）の熊本県ポリゴンに入るかどうか。スクリプトが初回に配布元からダウンロードします
- **メッシュの緯度経度**: メッシュコード（9桁）から計算しています。1〜4桁目が1次メッシュ、5・6桁目が2次、7・8桁目が3次（1km）、9桁目がその4分割（1:南西 2:南東 3:北西 4:北東）。**メッシュのシェープファイルは要りません**
- **市区町村名**: N03の市区町村ポリゴンとの重ね合わせ。熊本市の区名はこの年次のN03の名称欄に入らないため、行政区域コード（43101〜43105）から補っています

発災前の平均を全メッシュで合計すると約162万人になります。10人未満のメッシュが配信されない分だけ県全体の人口より小さくなりますが、桁は合っています。

## 地図と時系列の読み方

- **色**は発災後（本震以降）と発災前の平均人口の比。減った側が青、増えた側が赤です。「深夜（2〜4時）」を選ぶと、ほぼ滞在人口の比較になり、昼間の移動に左右されずにその場所に残っているかを見られます
- **地図に出すメッシュ**は、既定では「常に10人以上」（336時点すべてで配信されたもの、3,834メッシュ）に絞っています。全26,798メッシュを描くとGeoJSONが8MBを超えてブラウザが重くなるためで、絞り込みは選択できます
- **平常時**は、発災前（07-21 00:00〜本震）の同じ日区分（平日／土／日祝）・同じ時刻の平均。**発災前は8日分しかないため、土・日祝はそれぞれ1日分の値です**（平日は6日分）。交通量側の平常時は2週間分から取っているので、同じ「平常時」でも厚みが違います
- **線が切れている**ところは、その時間帯に10人未満で配信されなかったことを示します。0人ではありません

## 分かっていないこと

- 提供データは推計値で、ドコモの契約者数から人口全体に拡大したものです。拡大の方法は提供元の公開情報の範囲でしか分かりません
- 500mメッシュの帰属は在圏の基地局情報に基づくため、メッシュ境界付近の帰属には誤差があります
- 避難所の滞在人数のような、施設単位の値は出せません（メッシュ内の合計しか分かりません）
