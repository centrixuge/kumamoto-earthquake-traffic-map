# 商用車プローブデータ

ダッシュボードの「商用車プローブ」タブの仕組みをまとめています。提供元は**トランストロン（受領済み）**と**日野データシステム（受け取り待ち）**の2社で、受け取ったものから順にこのタブへ足します。**分析結果の可視化は作業中**である旨をタブに明記し、いまはデータの配布だけを行っています。以下はトランストロンの分についてです。**このタブは develop（非公開URLの確認用アプリ）だけに置いています。** 公開アプリ（main）には出していません。

## 扱いの方針

- 提供元は株式会社トランストロン。項目の定義は同社の仕様書からの転記で、**この仕様書には「株式会社トランストロン秘密情報」の表示があります**
- **第三者への提供の可否は未確認です。** 確認が済むまで、配布データ・そこから作った束ねファイル・レイアウト表は、公開リポジトリにも公開アプリにも置きません
- **このリポジトリはブランチも含めて公開です。** アプリのURLが非公開でも、リポジトリに入れたものは公開されます。そのため**項目の定義・値域・断面リンクの一覧といった「データの中身」はリポジトリに置かず**、非公開の置き場に `transtron_layout.json` として置き、アプリが実行時に読んで表示します
- 置き場は `data/transtron/`（`.gitignore` 済み）。束ねた結果とレイアウトのJSONは `data/transtron/bundle/`

したがってこのページに書くのは、**処理の規則と仕組みだけ**です。データの中身はタブの中（レイアウト表・断面リンクの一覧）で見てください。

## all-in-one版の作り方

```bash
python scripts/build_transtron_bundle.py
```

配布は期間ごと・県ごと・日ごとに分かれ（いまは3配布・46ファイル）、粒度も途中で変わっています（前半は期間まとめ、後半は日別）。全期間を1本にまとめたものを作り、`data/transtron/bundle/` に3ファイル（gzip・UTF-8 BOM付き・CRLF）とメタ情報のJSONを出します。

**素朴に縦につなぐと二重に数えます。** 配布はトリップ単位で切り出されているため、期間の境をまたぐトリップは後の期間のファイルに入り、その結果**同じキー（断面リンク・日・時間帯・リンク）の行が隣のファイルにも現れます**。そこでキーで**合計**します。

合計でよいことは生データと突き合わせて確認しました（`scratch/transtron_crosscheck.py`）。断面リンク自身の行の台数を、生データから数え直したトリップ数と比べると:

| ルール | 一致した組の割合 | 複数ファイルに分かれていた組での一致 |
| --- | --: | --: |
| 合計 | 98.1% | ほぼ全部 |
| 最大（重複を捨てる） | 94.8% | 1組だけ |

残る不一致はいずれも**集計側が数台多い**方向のずれで、生データの空間範囲が切られている（＋日時の空欄がある）ぶん数え落ちるためと見ています。件数と内訳はタブの「足し合わせの裏付け」に出しています。

all-in-one版には、配布ファイルには無い列を足しています（`県`・`元ファイル数`・`配布`・`元ファイル`）。`元ファイル数` が2以上の行は足し合わせた行です。

## アプリからの配り方

タブの実装は [`modules/transtron.py`](../modules/transtron.py)。ファイルは次の順に探します（[`modules/private_store.py`](../modules/private_store.py) の共通処理で、モバイル空間統計と同じ）。

1. `data/transtron/bundle/`（手元での確認用）
2. 環境変数 `TRANSTRON_S3_BUCKET` / `TRANSTRON_S3_PREFIX`（AWSに移した後）
3. `st.secrets["transtron"]`（`repo` ＝ 非公開GitHubリポジトリ、または `base_url`）

どれも無ければタブは「準備中」と出して落ちません。

### いまの置き場: 非公開GitHubリポジトリ

**[centrixuge/kumamoto-transtron-probe-data](https://github.com/centrixuge/kumamoto-transtron-probe-data)（Private）** に置いています。モバイル空間統計とは別のリポジトリにしたのは、提供元が違い提供条件も別だからです（片方を誰かと共有したときに、もう片方まで一緒に渡らないようにする）。

デプロイ済みアプリ（develop）の secrets は次のように書きます。

```toml
[transtron]
repo = "centrixuge/kumamoto-transtron-probe-data"
ref  = "main"
token = "github_pat_..."   # Contents: Read-only の fine-grained PAT
```

PATは Repository access でこのリポジトリを選び、Repository permissions の **Contents: Read-only** だけを付けます（モバイル空間統計のトークンに、このリポジトリを足す形でもかまいません）。

GitHubのContents APIは raw で46.8MBのファイルも返します（実測5秒）。`modules/private_store.py` が組み立てるURLが、実際に通ったAPIのパスと一致することも確認しています。

将来S3へ移したら、`TRANSTRON_S3_BUCKET` を渡すだけで置き場が切り替わります（コードの変更は不要）。

大きいファイルを毎回読むとタブを開くだけで重くなるので、**「ファイルを用意する」を押してから**ダウンロードのボタンを出す2段構えにしています。それでも押した時点でアプリのメモリが**345MB → 439MB（+94MB）**に増えるのを実測しました（キャッシュした本体と、ウィジェットに渡す分の2つを持つため）。Streamlit Community Cloud の上限は1GBで、モバイル空間統計を読んだ状態が578MBなので、余裕は大きくありません。**S3に置いて署名付きURLを渡す形にすれば、アプリのメモリを使わずに配れます** — AWSへの移行（[docs/deploy-aws.md](deploy-aws.md)）と合わせて決めるのが良さそうです。

レイアウト表（Excel）とレイアウトのJSONは `scratch/` のスクリプトが作ります（中身が仕様書の転記なので、スクリプトもリポジトリに入れていません）。

## 分析にあたって足りないもの

配布データだけでは足りず、別途用意が必要なもの:

- **道路種別コード・道路管理者コードの定義表**。仕様書に定義表が付いていないため、値の意味はDRM（デジタル道路地図）の仕様で確認する必要があります
- **道路交通センサスのゾーン区分表**。集計ODの起終点はBゾーンコードで、市区町村までは下の規則で読み替えられますが、市区町村内のゾーン内訳にはこの表が要ります
- **DRMの線形データ**。2次メッシュ番号＋リンク番号でリンクが決まるので、地図に落とす・路線名を付ける・断面の位置を特定するのに必要です

外れ値と欠測（平均速度の跳ね、日時の空欄、配布の無い期間）については、実測した件数をタブの「分析にあたっての注意」に出しています。

### Bゾーンは市区町村まで読み替えられます

集計ODデータの起終点は7桁のBゾーンコードですが、手元のデータを調べると **7桁＝市区町村コード5桁＋ゾーン番号2桁**（ゾーン番号が1桁のときは右側が空白）でした。センサスのゾーン区分表が無くても、総務省の全国地方公共団体コードだけで市区町村まで読み替えられます。

`python scripts/build_bzone_table.py` が総務省の団体コード（令和6年1月1日現在）から `data/bzone/municipality_codes.csv`（1,965行）を作ります。**公的な公開データなのでリポジトリに置いてあり**、タブからCSVでダウンロードできます。読み替えは [`modules/bzone.py`](../modules/bzone.py)。

被覆率の実測はタブの中に出しています。合併・改称前のコード（センサスの時点のもの）はこの表に無いため取りこぼしが出ます。市区町村内のゾーン内訳まで要る場合は、道路交通センサスのゾーン区分表が別に必要です。

### DRMの扱い

DRM（デジタル道路地図）は**モバイル空間統計と同じ扱い**にします。つまり、データそのものは公開せず、**develop でもダウンロードさせません**（アプリの中でリンク番号を位置・路線名に読み替えるのに使うだけ）。置き場は `data/drm/`（`.gitignore` 済み）で、実データはまだ入手していません。
