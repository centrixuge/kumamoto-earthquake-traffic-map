# 手法と注意点

[README](../README.md) から分割したページです。平常時の定義、異常検知のしきい値、時系列ビューの違い、結果を読むうえでの制約をまとめています。

## 平常時（ベースライン）

**日区分ごとに別々**の1時間交通量です。曜日で交通量の形がまったく違うため、実測の各行は**自分と同じ日区分**の平常時と比べます。観測点×日区分×時刻(hour)ごとに平均・標準偏差を求めます。5分間値は過去1ヶ月しか遡れないのに対し1時間値は3ヶ月遡れるため、母集団を広く取れる1時間値を採用しています。1日の区切りは深夜帯を日付でまたいで切らないよう**03:00起点**にしており、日区分の判定もこの区切りで行います

| 日区分 | 定義 | 母集団 |
| --- | --- | --- |
| 月・火・水・木・金 | その曜日で祝日でない日 | 各曜日8日分（新しい順に遡る） |
| 土 | 土曜で祝日でない日 | 8日分 |
| 日祝 | 日曜、または平日・土曜にあたる祝日 | 8日分 |

祝日の扱いは[内閣府の祝日CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)で判定します。**祝日は曜日によらず「日祝」に入れます**（日曜はもともと休日なので祝日と重なっても傾向が変わらず、平日・土曜の祝日は日曜寄りの交通になるため）。祝日で除外された曜日は、8日を確保するためさらに前の週へ遡ります（例: 2026-07-20 海の日（月）は月曜の母集団から外れ、日祝に入り、月曜は5/25まで遡って8日を確保）。使った日は実行ログと `quake_info.json` の `hourly_baseline_daytypes` に残ります

**なぜ曜日を分けるか（実測）**: 火曜だけの平常時で評価すると、地震と無関係な平常時の土日でも**8割の行が異常判定**になりました（朝7時は火曜比0.68倍、深夜22時は1.99倍）。日区分別にしたうえで、母集団に入っていない土日（5/30・5/31）で検証すると誤検知は **71% → 12%** に下がりました

## 異常検知

1時間値どうしの比較で定義します。1時間値の実績と、**同じ日区分**の平常時の平均・標準偏差から `|zスコア| >= 2` を異常としてフラグ。**地図の色分けと異常検知一覧もこの1時間値ベースの判定に基づきます**

## 時系列の4ビュー

実績の既定は5分間値です。
- `5分間値`: 実績は5分間値。平常時は1時間値ベースなので単位を合わせるため1/12しています。**この帯は「平常時の1時間あたり交通量の日々のばらつき÷12」であり、5分間値そのもののばらつきではないため狭く出ます**（同梱データ時点では、5分間値どうしで求めたσの平均 8.2 に対して 3.0 程度）。細かい変動を追うのには使えますが、帯からの外れ具合を異常の根拠にはしないでください
- `1時間値`: 実績・平常時とも1時間値どうしの比較。異常検知の判定もこの粒度です
- `車種別・5分間値` / `車種別・1時間値`: 上り・下りの図はそのままに、**同じ図の中で小型車（濃い色）と大型車（明るい色）を分けて**表示します。選択1地点目は 赤＝小型／ピンク＝大型、2地点目は 緑＝小型／ライムグリーン＝大型。大型車は小型車の1割程度の水準なので、同じ縦軸でも下側に分かれて描かれます。線種で分ける案（大型を破線）は**平常時の点線と紛らわしい**ため採っていません。異常検知の判定は車種を合計した1時間値で行っており、この図で判定は変わりません。**5分間値のほうは大型車が5分あたり中央値4台（0台が14%）と粒度が粗く**線がぎざぎざになるため、水準の比較には1時間値のほうが向きます。平常時の帯は1時間値σの1/12なので、台数の小さい大型車では実際のばらつきより狭く出る影響がより大きくなります

**車種別で見える差（日区分・時刻をそろえた実測）**: 地震後、小型車は平常時の **92.6%**（−7.4%）まで下がったままなのに対し、大型車は **103.4%**（+3.4%）と平常時を上回って推移しています。合計交通量だけを見ると打ち消し合って見えません。なお API は車種判別不能の台数も返しますが、アーカイブ全期間で**1台**しかないため系列としては扱っていません

## 表示期間

時系列図の表示期間は画面上部のプルダウンで切り替えます。開始はどれも **2026-07-27 12:00** で共通なので、選択肢の名前には終端だけを書いています（データは `TARGET_START` の 07-27 03:00 から保持していますが、地震前日の深夜〜早朝は情報が薄いので表示から外しています）。

区切りは日付ではなく**本震発生（2026-07-28 16:27）からの経過時間**で置いています。日付で書くと何日目にあたるのかが読み取れないためです。ただし本震が16:27なので厳密にN日後で切ると日の途中で終わってしまうため、**その時点を含む日の24時**まで伸ばして日の区切りで終わるようにしています。

| 選択肢 | N日後の時点 | 終端 |
| --- | --- | --- |
| `発災後3日間` | 07-31 16:27 | 08-01 00:00 |
| `発災後1週間`（既定） | 08-04 16:27 | 08-05 00:00 |
| `発災後2週間` | 08-11 16:27 | 08-12 00:00（`RECOVERY_PERIOD` の上限＝収集の終端） |
| `最新3日間` | — | データの最終時刻（開始もその3日前） |

既定を最新までにしていないのは、データが復旧期まで伸び続けるため、放っておくと発災直後の変化が横に潰れて読めなくなるからです。発災後1週間なら落ち込みと戻り始めが1枚で読めます。データがまだ終端まで伸びていない期間を選んだ場合は、図の右側が空くだけです。

範囲を変えても軸を切り替えるだけで、集計や異常判定には影響しません。

## そのほかの扱いと制約

- **道路種別**: JARTICの `道路種別`（**1＝高速自動車国道 / 3＝一般国道** の2値のみ）をそのまま持っています。**常時観測点コードからは判別できません** — 全国1,058点を調べたところ、上位桁と種別の対応には反例があります（3桁目が6でないのに種別1が32点、6なのに種別3が7点）。APIは種別ごとに別リクエストなので、両方を取得して結合しています。地図では**高速自動車国道を■、一般国道を●**で描き分けます（色は異常度に使っているため、種別は形で分けています）
- **観測点のID**: JARTICの「常時観測点コード」（例 `9110030`）を観測点の識別子として使い、地図・セレクタ・グラフ凡例・CSVで共通にしています。アーカイブにはこの列を持たない時期のデータも含まれるため、`data/stations.json`（コードと緯度経度の対応表）を経由して後から付け直しています（座標はAPIの応答で末尾の桁がわずかに揺れるため、5桁≒1mに丸めて突き合わせ）
- **地震前からの規制を分けて表示**: 2020年7月豪雨による通行止めのように数年前から継続している規制が一覧に含まれるため、規制開始日時が本震以降かどうかで分類し、地図では別レイヤ・別の色にしています。これをしないと今回の地震によるものと見分けられません
- **地震後が欠測の観測点**: 地震発生と同時に配信が止まった観測点があります（`9310035`：1時間値は 2026-07-28 15:00 が最後）。この場合zスコアが定義できないため、地図では**灰色・破線の丸**で「異常なし」とは区別して表示し、ツールチップに最後に値があった時刻を出します。異常度の色分けからは外れますが、**配信が止まったこと自体が情報**なので地図から消さないようにしています
- **異常検知は原因を特定するものではありません**: 「平常時からの統計的な外れ」を見ているだけで、通行規制・迂回・自主的な外出抑制・観測機器の不調などが混ざります
- 観測点は現在12点です（一般国道9点・高速自動車国道3点）。エリア全体の交通を代表するものではなく、その地点で何が起きたかを見るものです
- 1時間値のアーカイブには、**2026-07-01 までしか配信されていない観測点（`9310183`）が1点含まれます**。分析対象期間（本震前日以降）にデータがないため、地図・時系列・異常検知には登場しませんが、ダウンロードできる1時間値CSVには残しています（取得できたものを消さない方針のため）

## 対象エリア・期間の設定

対象エリア・期間・ベースライン期間は [`fetch_and_prepare.py`](../fetch_and_prepare.py) の定数で固定値になっています。別の地震・地域で使う場合はここを書き換えてください

| 定数 | 意味 |
| --- | --- |
| `BBOX` | 対象エリア（現在は熊本県） |
| `MAINSHOCK_EID` | 本震の気象庁イベントID |
| `TARGET_START` | 分析対象期間の開始 |
| `RECOVERY_PERIOD` | 本震から何日後までを対象にするか（既定14日） |
| `BASELINE_WINDOWS` | 5分間値の平常時ウィンドウ |
| `HOURLY_BASELINE_DAYS_PER_TYPE` | 1時間値の平常時を日区分ごとに何日集めるか（既定8） |
| `MIN_AFTERSHOCK_INTENSITY` | 時系列図に印を付ける地震の最大震度のしきい値（既定 震度5弱） |

**動的取得期間**: 対象期間の終端は「本震発生時刻 + `RECOVERY_PERIOD`（既定2週間）」まで動的に伸びていきます。被災後72時間はもちろん、交通が平常に戻っていく復旧期の推移まで追えるようにするためです
