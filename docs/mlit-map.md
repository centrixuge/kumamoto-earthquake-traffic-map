# 「通れる道マップ」の配布データ（既定の地図）

[README](../README.md) の「できること」から分割したページです。ダッシュボードの「地図・交通量の時系列変化」タブ（既定）で使っているデータについてまとめています。

現在のダッシュボードの通行規制は、県の公開JSON＋PDFからの手作業の転記という3つの経路で集めています（[docs/regulations.md](regulations.md)）。こちらは国土交通省が災害のたびに公開する「[通れる道マップ](https://www.mlit.go.jp/road/saigai/r8kumamoto/index.html)」の配布データだけで作った別系統です。国の配信で収録が揃っており、高速道路の緊急車両の通行可能区間まで区間ごとの線で入るため、**こちらを既定のタブにしています**（転記の版は「（参考）」タブ）。

## 配布されているもの

各時点のスナップショットがZIPで配られます。ZIPの中身は時点によってまちまちです。

| 収録 | 内容 |
| --- | --- |
| 道路規制情報 | `dourokisei.geojson`。22時点に収録 |
| ETC2.0速度情報 | `ETC2.0_speed_data*.geojson`。23時点すべてに収録 |
| 通行実績情報 | `tukoujisseki*.geojson`。21時点に収録 |

- 手元に保存したZIPは [`data/mlit_r8kumamoto_map/`](../data/mlit_r8kumamoto_map)（23ファイル）
- 時点ごとの収録状況と、道路規制情報の属性・レコードの型の整理は、同じフォルダの `通れる道マップ_データ一覧.xlsx`（[`scripts/build_mlit_map_index.py`](../scripts/build_mlit_map_index.py) が生成）
- **配布元は最新版しか置いていません。** 過去の時点は再取得できないため、ダウンロードしたZIPをそのままリポジトリに残しています

日時はファイル名の `YYMMDDhhmm` から読みます（例 `2608071600` → 2026/08/07 16:00）。時刻の無い1件だけは、配布元の `notice.txt` の記載（as of 2026/07/29 8:00）に従いました。8/7 16:00 の回は規制情報のみ10:00時点です。

## 道路規制情報の中身はレコードごとに違う

1つの `dourokisei.geojson` に、属性の組み合わせが違うレコードが混ざっています。全時点を通じて全件が持っている属性は `道路種別`・`路線名`・`規制種別`・`規制理由` の4つだけで、住所や緯度経度、開始日時すら全件には入っていません。

| レコードの型 | 持っている属性 | 道路種別の内訳（全時点の合計） |
| --- | --- | --- |
| 災害詳細つき | 住所・座標・開始日時＋地整番号・整備局名・県番号・規制変更_日時/内容・迂回路/孤立集落/人身/物損/停電_有無 | 補助国道 9 |
| 方向・規制延長つき | 住所・座標・開始日時＋規制方向・規制延長_Km | 高速道路 38、直轄国道 26 |
| 区間名のみ | 始点・終点が地点名（IC名など）。住所・座標・開始日時のいずれも持たない | 高速道路 79、一般国道 3 |
| 属性なし | 整理IDだけで属性が無い線（紫・半透明） | （値なし）39 |
| 住所・座標・日時 | 住所・緯度経度・規制開始_日時・延長_Km | 都道府県道 329、補助国道 41、市区町村道 25、国道445号 1 |

型の名前は「どの属性を持つか」だけで付けています。データのどこにも出所は書かれていないので、県が出したものか国が出したものかは分かりません。

`道路種別` の値自体にも揺れがあります（「一般国道」「補助国道」「直轄国道」が混在、`道路種別` の欄に路線名「国道445号」が入っている1件）。この列だけで管理者を判別する処理を書くと、この揺れを踏みます。

## 状態（規制中／解除済み）の決め方

配布されるのは時点ごとのスナップショットで、1件ずつに解除日時は入っていません。そこで時点をまたいで同じ規制を追いかけます（[`scripts/build_mlit_map_regulations.py`](../scripts/build_mlit_map_regulations.py)）。

- 識別子は **線形のハッシュ＋路線名＋開始日時＋始点**。整理ID（`name`）は3割ほどのレコードにしか入っていないので使えません。線形は時点をまたいで一致します（08/04→08/07 で 44/44 一致を実測）
- **規制中** = 最新時点にも残っている。**その最新時点は 2026-08-14 09:00 です**。交通量は最新まで表示されますが、この時点より後の規制の変化は地図に出ていない（8/7 16:00 の回のように、配布の回と中の規制情報の時点がずれることがあるため、ずれる回は `REGULATION_AS_OF` で補正している）
- **解除済み** = 途中の時点で消えた。消えていた最初の時点を「解除の確認時点」として記録します。**解除の時刻は配布の間隔（半日〜3日）より細かくは分かりません**

22時点から通算110件になります。

| 道路種別 | 規制中 | 解除済み | 元データの道路種別 |
| --- | --: | --: | --- |
| 高速自動車国道 | 5 | 17 | 高速道路 |
| 一般国道 | 7 | 9 | 直轄国道・補助国道・一般国道 |
| 県道・市区町村道 | 28 | 30 | 都道府県道・市区町村道 |
| 不明（地図では解除済みの扱い） | 13 | 1 | （値なし） |

段階の分け方は、現在の地図の観測点の描き分け（JARTICの道路種別 1＝高速自動車国道 / 3＝一般国道）に合わせ、観測点の無い県道・市区町村道を3つ目に置いたものです。JARTIC側は直轄と補助を区別しないため、一般国道として束ねています。

**道路種別が取れないレコードが14件あります。** うち13件は配布GeoJSONに道路の線形（LineString）だけが入っていて、路線名・区間・規制内容・開始日時のどれも持ちません（残り1件は国道324号 合津IC〜知十IC の「通行止め解除」）。**このレコードは地図では「規制中」として出さず、解除済みの扱いで残します**（レイヤ一覧の「不明：解除済み」で切り替え、既定は非表示）。配布元の地図でも凡例に無い紫色で描かれており、いまの配布分については不備と見られるためで、そこに規制があったという記録は消さずに残す、という扱いです。データの「状態」そのものは書き換えていないので、一覧・CSV・GeoJSONには最新の配布にあるかどうかがそのまま入ります（いまは13件が規制中）。なお、この属性なしのレコードは配布のたびに出たり消えたりしています — 現れたのは22時点中4時点（07-31 08:00・07-31 16:00・08-01 18:00 に13件、08-11 15:00 に2件、08-14 09:00 に13件）で、間の10時点には1件も入っていません。

## 今回の災害より前からの規制は入っていない

開始日時を持つレコードの最も古い値が本震と同時（2026-07-28 16:27）で、規制種別も災害89件・点検1件です。**このデータは今回の災害に限った配信で、県の公開JSONにある2020年7月豪雨のような長期規制（42件）は含まれません。** そのためこのタブでは「災害前からの規制」の区分を表示していません（判定しても全件が災害後になり、かつ開始日時を持たないレコードが30件あって判定できないため）。

既定のタブと（参考）タブで規制の件数や種類が違うのは、この収録範囲の違いによるものです。

**「通行止め解除」とだけ書かれたレコードは地図に出していません**（3件）。規制ではなく解除の告知で、解除後に残る規制（対面通行など）も書かれていないためです。色を割り当てても意味が無いので、地図・凡例からは外し、一覧には残しています。対面通行や片側交互の記載が来た場合は、その内容で色を付けます（第17報の宮原SA〜八代ICの対面通行は、いまのところNEXCOのPDFにしか出ていないため（参考）タブのツールチップにあります）。

## 取り出し方

地図の下の「規制の一覧」から、CSVとGeoJSONで取得できます。**線形が入るのはGeoJSONだけ**です。どちらにも、時点をまたいだ突き合わせの結果（状態・初出時点・最終確認時点・解除の確認時点・出現時点数）が入ります。

```bash
python scripts/build_mlit_map_index.py        # 時点ごとの一覧（Excel）
python scripts/build_mlit_map_regulations.py  # data/mlit_map_regulations.json を作る
streamlit run app_mlit_map.py                 # 規制の地図だけを単体で確認する
```

新しい時点のZIPを配布元からダウンロードしたら、`data/mlit_r8kumamoto_map/` に置いて上の2つを実行し直します。ファイル名の日時から自動で読み取るので、他に手を入れる箇所はありません。
