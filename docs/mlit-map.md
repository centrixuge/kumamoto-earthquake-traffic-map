# 「通れる道マップ」の配布データ（既定の地図）

[README](../README.md) の「できること」から分割したページです。ダッシュボードの「地図・交通量の時系列変化」タブ（既定）で使っているデータについてまとめています。

現在のダッシュボードの通行規制は、県の公開JSON＋PDFからの手作業の転記という3つの経路で集めています（[docs/regulations.md](regulations.md)）。こちらは国土交通省が災害のたびに公開する「[通れる道マップ](https://www.mlit.go.jp/road/saigai/r8kumamoto/index.html)」の配布データだけで作った別系統です。国の配信で収録が揃っており、高速道路の緊急車両の通行可能区間まで区間ごとの線で入るため、**こちらを既定のタブにしています**（転記の版は「（参考）」タブ）。

## 配布されているもの

各時点のスナップショットがZIPで配られます。ZIPの中身は時点によってまちまちです。

| 収録 | 内容 |
| --- | --- |
| 道路規制情報 | `dourokisei.geojson`。33時点に収録 |
| ETC2.0速度情報 | `ETC2.0_speed_data*.geojson`。34時点すべてに収録 |
| 通行実績情報 | `tukoujisseki*.geojson`。30時点に収録 |

- 手元に保存したZIPは [`data/mlit_r8kumamoto_map/`](../data/mlit_r8kumamoto_map)（34ファイル）
- 時点ごとの収録状況と、道路規制情報の属性・レコードの型の整理は、同じフォルダの `通れる道マップ_データ一覧.xlsx`（[`scripts/build_mlit_map_index.py`](../scripts/build_mlit_map_index.py) が生成）
- **配布元のページには過去の回のZIPも並んでいます**（2026-09-01 時点で33回ぶん）。以前「最新版しか置いていない」と書いていましたが誤りでした。取りこぼした回は後から拾えます。それでも、ダウンロードしたZIPはそのままリポジトリに残しています（配布が消える可能性はあるため）

日時はファイル名の `YYMMDDhhmm` から読みます（例 `2608071600` → 2026/08/07 16:00）。時刻の無い1件だけは、配布元の `notice.txt` の記載（as of 2026/07/29 8:00）に従いました。8/7 16:00 の回は規制情報のみ10:00時点です。

## 道路規制情報の中身はレコードごとに違う

1つの `dourokisei.geojson` に、属性の組み合わせが違うレコードが混ざっています。全時点を通じて全件が持っている属性は `道路種別`・`路線名`・`規制種別`・`規制理由` の4つだけで、住所や緯度経度、開始日時すら全件には入っていません。

| レコードの型 | 持っている属性 | 道路種別の内訳（全時点の合計） |
| --- | --- | --- |
| 災害詳細つき | 住所・座標・開始日時＋地整番号・整備局名・県番号・規制変更_日時/内容・迂回路/孤立集落/人身/物損/停電_有無 | 補助国道 9 |
| 方向・規制延長つき | 住所・座標・開始日時＋規制方向・規制延長_Km | 高速道路 38、直轄国道 26 |
| 区間名のみ | 始点・終点が地点名（IC名など）。住所・座標・開始日時のいずれも持たない | 高速道路 79、一般国道 3 |
| 属性なし | 整理IDだけで属性が無い線（紫・半透明） | （値なし）39 |
| 住所・座標・日時 | 住所・緯度経度・規制開始_日時・延長_Km | 都道府県道 329、補助国道 41、市区町村道 25、国道445号 1 |

型の名前は「どの属性を持つか」だけで付けています。データのどこにも出所は書かれていないので、県が出したものか国が出したものかは分かりません。

`道路種別` の値自体にも揺れがあります（「一般国道」「補助国道」「直轄国道」が混在、`道路種別` の欄に路線名「国道445号」が入っている1件）。この列だけで管理者を判別する処理を書くと、この揺れを踏みます。

## 配布が止まっていることがある（重要）

**配布の回が新しくても、中の道路規制情報が前の回の使い回しであることがあります。** 実測: 2026-08-31 16:00 の回に入っている `dourokisei.geojson` は、08-25 09:00 の回のものと**バイト単位で同一**でした（配布元の `map.zip`＝サイトの地図が読むファイルも同じもの）。

そのままだと「最新の配布＝最新の規制」と誤って読めるので、[`scripts/build_mlit_map_regulations.py`](../scripts/build_mlit_map_regulations.py) が**規制情報のハッシュを取り、前の回と同じなら規制の時点を前の回のものとして扱います**（`latest_regulation_time`）。何日ぶん止まっているかは `regulation_stale_days` に入れ、地図の上にも出します。

### ほかの資料で解除を拾う

配布が止まっている間の解除は、このデータだけでは分かりません。そこで、ほかの2つの資料と突き合わせています。

| 資料 | 対象 | 更新 |
| --- | --- | --- |
| 熊本県の公開JSON | 県道・市区町村道・補助国道 | 6時間ごとに自動取得 |
| NEXCO西日本・熊本河川国道事務所の報（PDFからの転記） | 高速道路・直轄国道 | 報が出るたびに転記 |

**高速道路と直轄国道は県の公開JSONに載りません。** そのぶんは転記で拾います。

**県の公開JSONとの突き合わせ**

- 路線名をそろえて（`県道17号坂本人吉線` → `坂本人吉線`）一致を探し、**端点が3km以内**なら同じ区間とみなす
- 県側が「解除」または終了日時が過ぎていれば、**地図でも解除済み（灰色）として出す**
- 照合の中身（県側の路線名・内容・終了日時・距離）は各件の `県フィード照合` に残し、線をなぞるとツールチップに出ます

照合は2段階です。まず**区間単位**（同じ路線・端点3km以内）で探し、見つからない場合でも**その路線について県が持っている規制がすべて解除済みなら、路線単位で解除**と見ます（県道・市区町村道だけ。高速道路・直轄国道は県のフィードに載らないので、この判定はしません）。どちらで判定したかは各件の `判定根拠` に入れ、ツールチップにも出します。

**転記との突き合わせ**

高速道路・直轄国道は、路線名の鍵（`E3A 南九州自動車道` も `E3南九州自動車道（西回り）` も `南九州自動車道`）が一致し、**規制の種類（全面通行止め／緊急車両のみ／片側交互など）も一致**し、線形から端点までが3km以内のものだけを同じ区間とみなします。**道路が並走しているので（国道3号と南九州道など）、線形の近さだけで突き合わせると取り違えます。** 種類までそろえるのは、同じ道路の別の規制（全面通行止めと舗装補修の片側交互）を混同しないためです。

2026-09-01 時点では、配布に残っている39件のうち**26件が照合でき、17件が解除済み**でした（県の公開JSONで14件・転記で3件）。地図の規制中は **39件 → 22件** になります。まだ通行止めの E3A南九州道 八代JCT〜八代南IC は、転記の終了日時が空なので規制中のまま残ります。

**突き合わせに使う `data/regulations.json` が古いと取りこぼします。** 自動取得は main にしかコミットされないので、作業ブランチで作り直すときは `git checkout origin/main -- data/regulations.json` で新しくしてから実行してください（スクリプトは使ったファイルの更新時刻を表示し、2日以上古いと警告します）。

## 状態（規制中／解除済み）の決め方

配布されるのは時点ごとのスナップショットで、1件ずつに解除日時は入っていません。そこで時点をまたいで同じ規制を追いかけます（[`scripts/build_mlit_map_regulations.py`](../scripts/build_mlit_map_regulations.py)）。

- 識別子は **線形のハッシュ＋路線名＋開始日時＋始点**。整理ID（`name`）は3割ほどのレコードにしか入っていないので使えません。線形は時点をまたいで一致します（08/04→08/07 で 44/44 一致を実測）
- **規制中** = 最新時点にも残っている。**その最新時点は 2026-08-31 16:00 です**。交通量は最新まで表示されますが、この時点より後の規制の変化は地図に出ていない（8/7 16:00 の回のように、配布の回と中の規制情報の時点がずれることがあるため、ずれる回は `REGULATION_AS_OF` で補正している）
- **解除済み** = 途中の時点で消えた。消えていた最初の時点を「解除の確認時点」として記録します。**解除の時刻は配布の間隔（半日〜3日）より細かくは分かりません**

33時点から通算110件になります。

| 道路種別 | 規制中 | 解除済み | 元データの道路種別 |
| --- | --: | --: | --- |
| 高速自動車国道 | 4 | 18 | 高速道路 |
| 一般国道 | 7 | 9 | 直轄国道・補助国道・一般国道 |
| 県道・市区町村道 | 28 | 30 | 都道府県道・市区町村道 |
| 不明（地図では解除済みの扱い） | 0 | 14 | （値なし） |

段階の分け方は、現在の地図の観測点の描き分け（JARTICの道路種別 1＝高速自動車国道 / 3＝一般国道）に合わせ、観測点の無い県道・市区町村道を3つ目に置いたものです。JARTIC側は直轄と補助を区別しないため、一般国道として束ねています。

**道路種別が取れないレコードが14件あります。** うち13件は配布GeoJSONに道路の線形（LineString）だけが入っていて、路線名・区間・規制内容・開始日時のどれも持ちません（残り1件は国道324号 合津IC〜知十IC の「通行止め解除」）。**このレコードは地図では「規制中」として出さず、解除済みの扱いで残します**（レイヤ一覧の「不明：解除済み」で切り替え、既定は非表示）。配布元の地図でも凡例に無い紫色で描かれており、いまの配布分については不備と見られるためで、そこに規制があったという記録は消さずに残す、という扱いです。データの「状態」そのものは書き換えていないので、一覧・CSV・GeoJSONには最新の配布にあるかどうかがそのまま入ります（**8/19以降の回には1件も入っていないため、いまは14件すべて解除済みです**）。なお、この属性なしのレコードは配布のたびに出たり消えたりしています — 現れたのは33時点中6時点（07-31 08:00・07-31 16:00・08-01 18:00 に13件、08-11 15:00 に2件、08-14 09:00 に13件、08-18 09:00 に2件）で、ほかの27時点には1件も入っていません。

## 今回の災害より前からの規制は入っていない

開始日時を持つレコードの最も古い値が本震と同時（2026-07-28 16:27）で、規制種別も災害89件・点検1件です。**このデータは今回の災害に限った配信で、県の公開JSONにある2020年7月豪雨のような長期規制（42件）は含まれません。** そのためこのタブでは「災害前からの規制」の区分を表示していません（判定しても全件が災害後になり、かつ開始日時を持たないレコードが30件あって判定できないため）。

既定のタブと（参考）タブで規制の件数や種類が違うのは、この収録範囲の違いによるものです。

**「通行止め解除」とだけ書かれたレコード5件は地図に出していません**（地図に出すのは110件のうち105件で、件数の表もその105件です）。規制ではなく解除の告知で、解除後に残る規制（対面通行など）も書かれていません。同じ区間の規制じたいは解除済み（灰色の破線）として地図に出ているので、解除されたことはそちらで読めます。一覧・CSV・GeoJSONには全110件が入っています。対面通行や片側交互の記載が来た場合は、その内容で色を付けます（第17報の宮原SA〜八代ICの対面通行は、いまのところNEXCOのPDFにしか出ていないため（参考）タブのツールチップにあります）。

## 地図の描き分け

色は「いまの状態」を先に読めるようにしています。

| | 色 | 線 | 既定 |
| --- | --- | --- | --- |
| 規制中 | 規制の内容ごと（全面通行止め＝赤、緊急車両のみ＝橙、対面通行・片側交互＝黄、内容不明＝暗い灰青） | 実線 | 表示 |
| 解除済み | **内容によらず灰色** | 破線 | **表示** |

線の太さは道路種別（高速＞国道＞県道・市区町村道）で、レイヤの区切りと同じです。**重なりの順は「解除済みの上に規制中」で固定**しています（Leafletのpaneをz-index 396／398で分けており、レイヤをオン・オフしても入れ替わりません）。観測点はさらにその上（400）に置いて、規制の線に隠れないようにしています。レイヤ一覧の並びは従来どおり規制中が先です。

**解除済みも既定で表示します。** このタブの交通量は既定で「発災後1週間」を出しており、その頃に効いていた規制はいまはほとんど解除済みです。隠してしまうと、交通量が落ちた場所に規制があったことが地図から読めません。灰色にしているのは、いま効いている規制（赤）と見分けるためで、**解除済みまで内容で色分けすると地図の赤の大半が「もう解除された規制」になり、いま通れない場所が読み取れなくなる**ためでもあります。解除済みの内容は、線をなぞったときのツールチップ（開始日時・解除の確認時点つき）と下の一覧で見られます。

凡例は「規制中の色（規制の内容）」「解除済み」「線の太さ（道路種別）」の3行に組み替えました（以前は「色＝規制の内容」「破線＝解除済み」の2行で、解除済みに灰色を割り当てると食い違うため）。

線形が入っておらず1地点だけのレコード（国道445号 八代市泉町葉木）は、同じ色の小さい丸で描いています（foliumに任せると既定の青いピンになり、色の規則から外れるため）。

## 交通量の表示期間に連動させている

地図に出すのは、**交通量のグラフで選んでいる期間に効いていた規制だけ**です。期間は既定の選択肢（発災後3日間〜全期間）のほか、**「期間を指定」を選ぶと開始日・終了日を直接入れられます**（開始日の0:00から終了日の24:00まで。指定できる範囲は、選んでいる集計方法のデータがある範囲）。交通量が落ちた時期と規制の対応を、同じ期間で読めるようにするためです。期間を「発災後3日間」に切り替えると91件、「発災後1週間」で101件、「全期間」で105件になります（規制中と解除済みの合計）。日付を指定した場合も同じで、たとえば 8/10〜8/20 なら59件（うち39件はいまも規制中）、8/25〜8/31 なら39件すべてが規制中です。

判定は **[初出時点, 解除確認時点)** と表示期間が重なるかどうかで行います。**配布データには規制の開始・解除の時刻そのものが入っていない**ので、配布に現れた回・消えた回で代用しており、**配布の間隔（半日〜3日）より細かくは切れません**。最初の配布（2026-07-29 12:00）より前に始まって解除された規制は、そもそもこのデータに入っていません。

色は**現在の状態**のままです（赤＝いまも規制中、灰色の破線＝すでに解除済み）。選んだ期間の中での状態ではありません。

**地図の下の「規制の一覧」とCSV・GeoJSONは、期間で絞らず全期間の記録**を出します（記録として残すため）。地図と件数が違って見えるので、その旨を一覧の先頭に書いています。

## 取り出し方

地図の下の「規制の一覧」から、CSVとGeoJSONで取得できます。**線形が入るのはGeoJSONだけ**です。どちらにも、時点をまたいだ突き合わせの結果（状態・初出時点・最終確認時点・解除の確認時点・出現時点数）が入ります。

```bash
python scripts/build_mlit_map_index.py        # 時点ごとの一覧（Excel）
python scripts/build_mlit_map_regulations.py  # data/mlit_map_regulations.json を作る
streamlit run app_mlit_map.py                 # 規制の地図だけを単体で確認する
```

新しい時点のZIPを配布元からダウンロードしたら、`data/mlit_r8kumamoto_map/` に置いて上の2つを実行し直します。ファイル名の日時から自動で読み取るので、他に手を入れる箇所はありません。
