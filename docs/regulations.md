# 通行規制データの欠落と、直轄国道・高速道路の手動転記

[README](../README.md) の「データソース」から分割したページです。交通量が0でも、その原因となる規制が地図に出てこない場合があります。理由は2つあり、どちらもデータの性質に由来します。

## 通行規制データに載らない規制がある

通行規制は道路の管理者ごとに公表の仕方が違い、3つの経路で集めています（これは「(旧版)道路規制×交通量」タブで使っている系統です。既定のタブは国土交通省「通れる道マップ」の配布データ1本で、そちらは [docs/mlit-map.md](mlit-map.md) にまとめています）。

| 規制の対象 | 出典（公表ページ） | 集め方 | 手元のデータ |
| --- | --- | --- | --- |
| ① 県・市町村が管理する道路（補助国道・県道・市町村道） | 熊本県「[防災情報くまもと](https://portal.bousai.pref.kumamoto.jp/)」の[通行規制情報](https://portal.bousai.pref.kumamoto.jp/?p=traffic) | 公開JSONを6時間ごとに自動取得 | [`data/archive/regulations_archive.json`](../data/archive/regulations_archive.json)（追記専用） |
| ② 直轄国道・直轄の高規格道路（8件） | 国土交通省 九州地方整備局 [熊本河川国道事務所](https://www.qsr.mlit.go.jp/kumamoto/)「事務所からのお知らせ」 | PDFを手作業で転記 | [`data/qsr_regulations/`](../data/qsr_regulations)（PDF）→ [`data/mlit_regulations.json`](../data/mlit_regulations.json) |
| ③ 高速道路（NEXCO西日本管理・8件） | [NEXCO西日本](https://www.w-nexco.co.jp/) 九州支社「令和8年熊本地震による通行止め・災害状況等について（第○報）」 | PDFを手作業で転記 | [`data/nexco_west_regulations/`](../data/nexco_west_regulations)（PDF）→ [`data/nexco_regulations.json`](../data/nexco_regulations.json) |

同じ表をダッシュボードの地図の下にも出しています。②③は自動取得ではないため、新しい報が出ても手を入れるまで反映されません（手順は末尾）。

高速道路の区間の線形は、一般国道と違う方法で作っています。両端をルーティングで結ぶ方式は**実延長の2〜4倍・路線上52〜71%** という結果になり使えませんでした（上下線が別wayであることなどが原因）。代わりに、OSMで当該路線の名前を持つ道路のノードを200mおきに拾い、**A→B方向への進み具合で並べて、直前に選んだ点に最も近いものを繋ぐ**方式にしています。経路探索をしないので路線から外れず、延長も直線距離の1.05〜1.28倍に収まりました。


交通量が0になっていても、その原因となる規制が地図に出てこないことがあります。理由は2つあります。

**① 管理者の違い（構造的な欠落）**

「防災情報くまもと」の通行規制情報は**県・市町村が管理する道路**が対象です。国道も入りますが、県が管理する**補助国道だけ**です（実データ65件の内訳は 補助国道15件・県道42件・市道8件で、国道は 218/219/265/266/324/442/443/445号）。**国が管理する直轄国道（国道57号・3号など）の規制は最初から載りません**。

実例として、**国道57号 北側復旧道路（阿蘇西IC〜大津IC）は本震と同時（2026-07-28 16:27）に全面通行止め**となり、うち車帰IC〜大津IC が翌 **02:00 に解除**されました（熊本河川国道事務所 道第1〜3報）。この区間には常時観測点 `9310127` があり、地震直前は5分あたり約81台だった交通量が0になっています。**02:00 に交通量が再開しており、公表された解除時刻と一致します。**

これらの規制はポータルのデータに存在しないため、PDFから転記して `data/mlit_regulations.json` に持ち、ダッシュボードでは次のように扱っています。

- PDFは区間を「○○IC〜○○IC」と名前で示すだけで座標がありませんが、実在する道路区間なので**端点のICの座標から線形を復元**して別レイヤに描いています。端点は OpenStreetMap の `highway=motorway_junction` ノード（ノードIDを固定値で保持）、その間を OSRM でルーティングして道路網に沿った線にしています（[`scripts/build_mlit_paths.py`](../scripts/build_mlit_paths.py)）。復元した延長はPDF記載の延長と並べて記録しており、ダッシュボード上でも確認できます
- キロポストで示された地点（`216K600` など）のように線形を作れないものは、掛かっていた観測点が分かる場合だけその**すぐ上**に **▲** を置きます（観測点の丸とは重ならない高さ。現在は該当なし）
- 該当観測点を選んだとき、**交通量のグラフに通行止め期間の帯**を表示します。ただし対応づけは裏付けの取れたものだけなので、**現在この帯が出るのは8件中1件（国道57号 北側復旧道路 車帰IC〜大津IC × 観測点 `9310127`）だけ**です。高速道路8件と県フィードの規制には対応づけがなく、帯は出ません
- 描き分けは3つの独立した軸で決めています。**色**＝規制の区分（赤＝全面/車両通行止め、橙＝片側交互など、青灰＝地震前からの規制）、**⊗の有無**＝今回の地震以降に始まったかどうか、**実線／破線**＝いま規制中か解除済みか（線も⊗の外円も同じ）。さらに場所の示され方で、区間なら線＋⊗、地点だけ分かるなら⊗のみになります。⊗はPDFの別添図で使われている記号に合わせたもので、観測点マーカー（塗りつぶしの丸）と見分けるためでもあります
- レイヤは**道路の管理者×状態**で分けています。管理者ごとに公表の経路が違うので、それがそのままレイヤの区切りになります。

  | 並び | レイヤ | 既定 |
  | --- | --- | --- |
  | 1 | 高速道路：規制中 | ON |
  | 2 | 直轄国道：規制中 | ON |
  | 3 | 県・市町村管理：規制中 | ON |
  | 4 | 高速道路：解除済み | OFF |
  | 5 | 直轄国道：解除済み | OFF |
  | 6 | 県・市町村管理：解除済み | OFF |
  | 7 | 県・市町村管理：地震前から | OFF |

  並びは**状態が先、データソースが後**です（状態は 規制中→解除済み→地震前から、データソースは 高速道路→直轄国道→県・市町村管理）。「地震前から」は①にしか現れません（②③は今回の地震に関する報だけを転記しているため）。記録している規制の多くはすでに解除済みなので（県フィード65件のうち地震後かつ継続中は16件）、既定では規制中だけを出します。区間の端点（IC）は独立したレイヤにせず、その区間と同じレイヤに入れているので、区間を消せば一緒に消えます（同じICが規制中と解除済みの両方の区間の端点になる場合は、レイヤごとに1つずつ置いています）
- 転記した規制の一覧はこのページに置き、ダッシュボードからはリンクします。縦に長く、地図を見ながら読む内容ではないためです。ダッシュボードの地図の下には、どこから何を集めたかの表（出典ページと収集済みPDFへのリンク）だけを出しています
- **区間の端点となるICも点（白丸・黒枠）で落とします**。線だけだとどのICからどのICまでなのかが地図から読めないためです。座標はOSMのICノードで、`endpoints` として `data/mlit_regulations.json` に保存しています。同じICが複数区間の端点になる場合（車帰ICは大津IC側と阿蘇西IC側の両方）は1点にまとめ、属する区間をツールチップに並べます。**まとめる単位はICの名前**です。同じICでも報によって座標が数十mずれていることがあり、座標で束ねると益城熊本空港ICが2つ描かれていました
  - **置くのは、その規制の区間の端点になっているICだけです。** 国道3号の舗装補修《第2弾》は区間を「松橋IC〜八代南IC の高速道路と並行する国道3号」と示していますが、この2つは高速道路のICであって国道3号の規制の端点ではないため、点は置いていません（松橋ICは高速道路の規制の端点としても出るので、二重にもなっていました）
  - **本文で言及されているIC・SA・PA**（川田橋の宇城氷川スマートIC〜八代IC、緊急車両が通れる八代南IC〜田浦ICなど）は、端点とは別に少し小さい点で置き、ツールチップに何の言及かを書いています。座標は同じくOSMのノードで、上下線に分かれているものは中点。NEXCOの各項目の `mentioned_points` に持たせています
  - 観測点のすぐ近くにあるIC（車帰ICと `9310127` は288m）は、県全体を映す既定のズームでは観測点マーカーの下に隠れます。拡大すると離れて見えるようになります

### 8月に追加された規制（道第6〜9報）

**国道3号の夜間片側交互通行（8/4〜8/7）は、交通量からは効果を切り出せません。** この4夜の22:00〜5:00は、同じ日区分・時刻の平常時に対して 9110040 が上り129〜184%・下り204〜281%、9110050 が上り157〜173%・下り246〜262% と、規制がありながら**むしろ大きく増えています**。同時期の道第1報（`260802_road6.pdf`）が、九州自動車道（松橋IC〜えびのIC）と南九州自動車道（八代JCT〜田浦IC）が上下線とも災害通行止めで国道3号に車両が集中していると伝えており、その転換分に埋もれているとみられます。これらの高速道路はNEXCO西日本の管理で、当初は日時が読み取れず登録していませんでしたが、その後にNEXCO西日本のPDFから転記して③として登録しています（下記）。

**国道57号北側復旧道路の夜間通行止め（8/5 21:00〜8/6 6:00）も同様です。** 規制区間は阿蘇西IC〜車帰ICの下り線で、観測点 `9310127` はその下流側の車帰IC〜大津IC区間にあります。当夜の下りは平常時の75.8%（上りは99.4%）と上流を塞がれた向きに整合しますが、**規制のなかった前夜が60.2%とさらに低い**ため、この規制によるものとは言えません。

同じ区間に日時の違う規制が複数ある場合（阿蘇西IC〜車帰ICは本震直後と8月の2件）、地図では線が完全に重なって下側のツールチップが出せなくなるため、**区間ごとに1本にまとめ、ツールチップに各期間を並べて**表示しています。

**高速道路のIC名で区間が示されている一般国道は、その高速と並行する国道の線を引きます。** 国道3号の舗装補修《第2弾》は、PDFの別添図が規制区間を「松橋IC〜八代南IC の高速道路と並行する国道3号」として示しています。両ICをOSMの国道3号上に投影し（それぞれ810m・369m）、その間をOSMの国道3号のノードを経由地にしてOSRMでルーティングしました。**端点間を直接ルーティングすると高速道路を通る経路になる**ため、経由地で国道上に縛っています。引いた線は**100%が国道3号から50m以内**（最大10m）に収まることを確認済みです。ただし実際の工事は区間内の12箇所の点であり、この25.84kmが全体にわたって同時に規制されていたわけではありません。

**地名しか無い場合は、道路名で絞ってから落とします。** 地名の重心をそのまま最寄り道路にスナップすると、**5地点すべてが並行する薩摩街道や無名の側道に着きます**（実測で確認）。OSMを道路名（`name=国道3号` など）で絞ってから最寄りノードを採ることで、目的の国道上に落とせます。

- 氷川町大野〜八代市岡町中（第1弾）は、両端の地名をこの方法で国道3号上に落とし、その間をルーティングしました（4.35km、100%が国道3号から50m以内）
- キロポストだけの2件（国道3号 216K600、国道57号 133K450）は区間ではなく1地点なので、丸印で置いています

**地名からの復元には誤差があります。** 地名の代表点は面の重心なので、道路まで距離があります（氷川町大野は939m、宇土市住吉は250m動かしています）。キロポストから直接求めた位置ではないため、地図上の丸は概略の位置です。その旨をツールチップにも出しています。

**まだ解除されていない規制は、期間の終わりを空にしています。** 国道3号の舗装補修《第2弾》（8/10〜、追加12箇所）は転記時点で解除の報が出ておらず、PDFにも「作業の進捗等により、交通規制予定日が変更になることがあります」と明記されています。PDF記載の予定日（8/14まで）を終了時刻として入れると、実際には続いている規制を地図上で「解除済み」（破線）と表示してしまうため、`end_timestamp` は空のままにし、予定期間は理由の欄に書いています。解除の報が出た時点で記入します。

**観測点との対応づけは推測で行っていません。** ダッシュボードはこの対応づけをもとに地図へ ▲ を置き、交通量のグラフに規制期間の帯を描くため、誤ると「規制のせいで交通量が落ちた」という誤った読み方を誘発します。裏付けが取れなかったものは対応づけせず、その理由を画面にそのまま出しています（例: 国道3号の最も近い観測点 `9110040` は規制開始より前から交通量がほぼ0で、規制中に回復しているため、この通行止めでは説明できない）。

第15報（8/11 8:00発表）で、8月11日9時頃に 八代IC〜坂本PA（工事用出入口を活用）が通行可能となり、**九州自動車道は全線で緊急車両が通れるようになりました**。第14報の時点では 松橋IC〜八代IC と 坂本PA〜えびのIC の2つに分かれていました。

**線では描き分けていません。** 通れる範囲が通行止めの区間と一致しないことがあり（南九州自動車道は一部だけ）、線を重ねると通行止めの線と紛らわしくなるうえ、坂本PAのようなPAはOSMのICノード（`highway=motorway_junction`）に無く、端点の座標を別に用意する必要があるためです。また、この情報は報のたびに変わるので、時点を必ず併記できる文字の形にしています。

**松橋IC〜えびのICの線には、人吉付近に約5.2kmの直線区間があります。** OSM上でその区間の道路名が変わるため拾えず、前後の点を直線で結んでいます（他の区間の点の間隔は0.2〜1.9km）。区間の位置を示すためのものなので線形の厳密さは意図していませんが、この箇所だけは実際の線形と離れます。

件ごとに根拠にした報（第○報とPDF名）は [`data/nexco_regulations.json`](../data/nexco_regulations.json) の `reports` に、線形の作り方は `path_source` に記録しています。PDFそのものは [`data/nexco_west_regulations/`](../data/nexco_west_regulations) にあります。国土交通省「[通れる道マップ](https://www.mlit.go.jp/road/saigai/r8kumamoto/index.html)」でも同じ区間を確認できます。

### 規制を追加するとき

高速道路（NEXCO西日本）については、**新しい報が出ていないかを1日2回（日本時間9:00と19:00）自動で見に行きます**（[`.github/workflows/check-nexco-reports.yml`](../.github/workflows/check-nexco-reports.yml)）。NEXCO西日本のトップページに並ぶPDFの表題から「第○報」を拾い、手元に無い番号があれば `data/nexco_west_regulations/` に保存し、読み取れる範囲（緊急車両の通行可能区間）を `data/nexco_regulations.json` に反映して、**`auto/nexco-report` から main へのプルリクエストを出します**（mainへ直接コミットはしません）。すでに開いているPRがあるときは、そのブランチに追記します。開いているPRが無ければ、ブランチはmainから切り直します（マージ済み・放置のブランチの古いコミットを引きずらないため）。

**作業ブランチを転記専用にしているのは、PRの差分を転記した分だけに保つためです。** developで作業すると、developに乗っている他の作業（モバイル空間統計の集計など）まで差分に入り、マージするとまとめてmainへ行ってしまいます。マージしたあとは、developにもmainを取り込んで揃えておきます。

PRの本文には、変更前後の対比・報から読み取った内容・**反映後に画面へ出る文言**（地図の下の注記と線のツールチップ。地図と同じ [`modules/nexco_text.py`](../modules/nexco_text.py) で作っているのでずれません）・判断が要るもの・確認用のURLを載せます。確認用アプリ（リポジトリ変数 `PREVIEW_APP_URL`）は既定でdevelopを映しているため、**このPRの内容はそこには出ません**。PR本文にもその旨が出ます。マージ前の画面を出先で確かめたい場合は、確認用アプリの向き先を `auto/nexco-report` に変え、リポジトリ変数 `PREVIEW_APP_BRANCH` に同じブランチ名を入れてください。手で確認するときは次を実行します。

```bash
python scripts/check_nexco_reports.py --dry-run   # 見るだけ
python scripts/check_nexco_reports.py             # 新しい報のPDFを保存
```

**自動化するのはここまでで、中身の転記はしません。** 区間・日時・緊急車両の通行可能区間の読み取りには判断が要り、取り違えたまま自動で公開されるほうが、気づくのが遅れるより害が大きいためです。報番号の付いていないお知らせ（お盆の交通混雑、無料措置など）も対象外にしていますが、実行ログには残るので見落としにはなりません。

新しい報が出たら、PDFを `data/qsr_regulations/`（直轄国道）または `data/nexco_west_regulations/`（高速道路）に置き、本文を確認して `data/mlit_regulations.json` / `data/nexco_regulations.json` の `items` に追記します。本文の確認には補助スクリプトを使えます（`pymupdf` が必要です。ダッシュボードの動作には不要）。

```bash
pip install pymupdf
python scripts/dump_qsr_pdf_text.py            # data/qsr_regulations/*.pdf 全部
python scripts/dump_qsr_pdf_text.py road2-4    # ファイル名で絞り込み
```

追記する項目の形式と注意点はスクリプトの docstring にまとめています。観測点がどの路線上にあるかは OSRM の nearest で確認できます。

```bash
curl -s "https://router.project-osrm.org/nearest/v1/driving/130.97624,32.91327?number=3"
```

区間の線形を作るには、端点のICを [`scripts/build_mlit_paths.py`](../scripts/build_mlit_paths.py) に追加して実行します。ICの座標は Overpass API で探せます（ノードIDを固定値で持たせ、実行ごとに結果が揺れないようにしています）。区間の示され方に応じて登録先が違います。

| 区間の示され方 | 登録先 |
| --- | --- |
| 直轄国道・高規格道路のIC名 | `IC_NODES` / `SECTION_ENDPOINTS`（ルーティング） |
| 並行する高速道路のIC名 | `PARALLEL_IC_NODES` / `PARALLEL_SECTIONS`（国道上に縛ってルーティング） |
| 地名 | `PLACE_POINTS` / `PLACE_SECTIONS`（道路名で絞ってスナップ） |
| 高速道路のIC名 | `EXPRESSWAY_IC_NODES` / `EXPRESSWAY_SECTIONS`（路線のノードを並べる） |

```bash
python scripts/build_mlit_paths.py --dry-run   # 延長の差を確認
python scripts/build_mlit_paths.py             # 2つのJSONに書き込む
```

**② 収集開始が本震より後（時間的な欠落）**

規制情報の収集を始めたのが本震の翌日であるため、県管理道路であっても**それ以前に解除された規制は残っていません**。アーカイブに記録が残っている最も古い時点はダッシュボード上に表示しています。
