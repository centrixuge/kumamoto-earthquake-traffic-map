# 通行規制データの欠落と、直轄国道の手動転記

[README](../README.md) の「データソース」から分割したページです。交通量が0でも、その原因となる規制が地図に出てこない場合があります。理由は2つあり、どちらもデータの性質に由来します。

## 通行規制データに載らない規制がある

通行規制は道路の管理者ごとに公表の仕方が違い、3つの経路で集めています。**県・市町村が管理する道路**は「防災情報くまもと」が公開JSONで配信しているので自動取得できますが、**国が管理する直轄国道**は熊本河川国道事務所のPDF、**高速道路**はNEXCO西日本の「お知らせ」PDFしか公表の手段がなく、どちらも手作業で転記しています（`data/mlit_regulations.json` と `data/nexco_regulations.json`）。

高速道路の区間の線形は、一般国道と違う方法で作っています。両端をルーティングで結ぶ方式は**実延長の2〜4倍・路線上52〜71%** という結果になり使えませんでした（上下線が別wayであることなどが原因）。代わりに、OSMで当該路線の名前を持つ道路のノードを200mおきに拾い、**A→B方向への進み具合で並べて、直前に選んだ点に最も近いものを繋ぐ**方式にしています。経路探索をしないので路線から外れず、延長も直線距離の1.05〜1.28倍に収まりました。


交通量が0になっていても、その原因となる規制が地図に出てこないことがあります。理由は2つあります。

**① 管理者の違い（構造的な欠落）**

「防災情報くまもと」の通行規制情報は**県・市町村が管理する道路**が対象です。実際に含まれている国道は補助国道（218/219/265/266/442/443/445号）だけで、**国が管理する直轄国道（国道57号・3号など）の規制は最初から載りません**。

実例として、**国道57号 北側復旧道路（阿蘇西IC〜大津IC）は本震と同時（2026-07-28 16:27）に全面通行止め**となり、うち車帰IC〜大津IC が翌 **02:00 に解除**されました（熊本河川国道事務所 道第1〜3報）。この区間には常時観測点 `9310127` があり、地震直前は5分あたり約81台だった交通量が0になっています。**02:00 に交通量が再開しており、公表された解除時刻と一致します。**

これらの規制はポータルのデータに存在しないため、PDFから転記して `data/mlit_regulations.json` に持ち、ダッシュボードでは次のように扱っています。

- PDFは区間を「○○IC〜○○IC」と名前で示すだけで座標がありませんが、実在する道路区間なので**端点のICの座標から線形を復元**して別レイヤに描いています。端点は OpenStreetMap の `highway=motorway_junction` ノード（ノードIDを固定値で保持）、その間を OSRM でルーティングして道路網に沿った線にしています（[`scripts/build_mlit_paths.py`](../scripts/build_mlit_paths.py)）。復元した延長はPDF記載の延長と並べて記録しており、ダッシュボード上でも確認できます
- キロポストで示された地点（`216K600` など）のように線形を作れないものは、掛かっていた観測点が分かる場合だけその**すぐ上**に **▲** を置きます（観測点の丸とは重ならない高さ。現在は該当なし）
- 該当観測点を選んだとき、**時系列図に通行止め期間の帯**を表示します
- 描き分けは3つの独立した軸で決めています。**色**＝規制の区分（赤＝全面/車両通行止め、橙＝片側交互など、青灰＝地震前からの規制）、**⊗の有無**＝今回の地震以降に始まったかどうか、**実線／破線**＝いま規制中か解除済みか（線も⊗の外円も同じ）。さらに場所の示され方で、区間なら線＋⊗、地点だけ分かるなら⊗のみになります。⊗はPDFの別添図で使われている記号に合わせたもので、観測点マーカー（塗りつぶしの丸）と見分けるためでもあります
- レイヤは**道路の管理者×状態**で分けています。管理者ごとに公表の経路が違うので、それがそのままレイヤの区切りになります。

  | 並び | レイヤ | 既定 |
  | --- | --- | --- |
  | 1 | 直轄国道：規制中 | ON |
  | 2 | 県・市町村道：規制中 | ON |
  | 3 | 直轄国道：解除済み | OFF |
  | 4 | 県・市町村道：解除済み | OFF |
  | 5 | 県・市町村道：地震前からの規制（工事・過去の災害等） | OFF |

  記録している規制の多くはすでに解除済みなので（県フィード65件のうち地震後かつ継続中は17件）、既定では規制中だけを出します。区間の端点（IC）は独立したレイヤにせず、その区間と同じレイヤに入れているので、区間を消せば一緒に消えます（同じICが規制中と解除済みの両方の区間の端点になる場合は、レイヤごとに1つずつ置いています）
- 地図の下に出典PDFへのリンク付きで一覧を出します
- **区間の端点となるICも点（白丸・黒枠）で落とします**。線だけだとどのICからどのICまでなのかが地図から読めないためです。同じICが複数区間の端点になる場合（車帰ICは大津IC側と阿蘇西IC側の両方）は1点にまとめ、属する区間をツールチップに並べます。座標はOSMのICノードで、`endpoints` として`data/mlit_regulations.json` に保存しています
  - 観測点のすぐ近くにあるIC（車帰ICと `9310127` は288m）は、県全体を映す既定のズームでは観測点マーカーの下に隠れます。拡大すると離れて見えるようになります

なお `9310127` には、**上記の規制では説明できない2回目のゼロ期間**があります。道第4報では 2026-07-29 08:00 に北側復旧道路の全区間が解除されていますが、交通量は同日 07:35 以降ほぼ0のまま（21:40までの約14時間で計10台）で、欠測ではなく実測の0です。原因は特定できていません（公表済みの報にこれを説明するものはありません）。**時系列図の帯は 16:27〜02:00 の通行止めのみを示すもので、その後のゼロ期間の原因を示すものではありません。**

### 8月に追加された規制（道第6〜9報）

**国道3号の夜間片側交互通行（8/4〜8/7）は、交通量からは効果を切り出せません。** この4夜の22:00〜5:00は、同じ日区分・時刻の平常時に対して 9110040 が上り129〜184%・下り204〜281%、9110050 が上り157〜173%・下り246〜262% と、規制がありながら**むしろ大きく増えています**。同時期の道第1報（`260802_road6.pdf`）が、九州自動車道（松橋IC〜えびのIC）と南九州自動車道（八代JCT〜田浦IC）が上下線とも災害通行止めで国道3号に車両が集中していると伝えており、その転換分に埋もれているとみられます。これらの高速道路はNEXCO西日本の管理で、PDFに規制の開始・解除日時が書かれていないため項目としては登録していません。

**国道57号北側復旧道路の夜間通行止め（8/5 21:00〜8/6 6:00）も同様です。** 規制区間は阿蘇西IC〜車帰ICの下り線で、観測点 `9310127` はその下流側の車帰IC〜大津IC区間にあります。当夜の下りは平常時の75.8%（上りは99.4%）と上流を塞がれた向きに整合しますが、**規制のなかった前夜が60.2%とさらに低い**ため、この規制によるものとは言えません。

同じ区間に日時の違う規制が複数ある場合（阿蘇西IC〜車帰ICは本震直後と8月の2件）、地図では線が完全に重なって下側のツールチップが出せなくなるため、**区間ごとに1本にまとめ、ツールチップに各期間を並べて**表示しています。

**高速道路のIC名で区間が示されている一般国道は、その高速と並行する国道の線を引きます。** 国道3号の舗装補修《第2弾》は、PDFの別添図が規制区間を「松橋IC〜八代南IC の高速道路と並行する国道3号」として示しています。両ICをOSMの国道3号上に投影し（それぞれ810m・369m）、その間をOSMの国道3号のノードを経由地にしてOSRMでルーティングしました。**端点間を直接ルーティングすると高速道路を通る経路になる**ため、経由地で国道上に縛っています。引いた線は**100%が国道3号から50m以内**（最大10m）に収まることを確認済みです。ただし実際の工事は区間内の12箇所の点であり、この25.84kmが全体にわたって同時に規制されていたわけではありません。

**地名しか無い場合は、道路名で絞ってから落とします。** 地名の重心をそのまま最寄り道路にスナップすると、**5地点すべてが並行する薩摩街道や無名の側道に着きます**（実測で確認）。OSMを道路名（`name=国道3号` など）で絞ってから最寄りノードを採ることで、目的の国道上に落とせます。

- 氷川町大野〜八代市岡町中（第1弾）は、両端の地名をこの方法で国道3号上に落とし、その間をルーティングしました（4.35km、100%が国道3号から50m以内）
- キロポストだけの2件（国道3号 216K600、国道57号 133K450）は区間ではなく1地点なので、丸印で置いています

**地名からの復元には誤差があります。** 地名の代表点は面の重心なので、道路まで距離があります（氷川町大野は939m、宇土市住吉は250m動かしています）。キロポストから直接求めた位置ではないため、地図上の丸は概略の位置です。その旨をツールチップにも出しています。

**まだ解除されていない規制は、期間の終わりを空にしています。** 国道3号の舗装補修《第2弾》（8/10〜、追加12箇所）は転記時点で解除の報が出ておらず、PDFにも「作業の進捗等により、交通規制予定日が変更になることがあります」と明記されています。PDF記載の予定日（8/14まで）を終了時刻として入れると、実際には続いている規制を地図上で「解除済み」（破線）と表示してしまうため、`end_timestamp` は空のままにし、予定期間は理由の欄に書いています。解除の報が出た時点で記入します。

**観測点との対応づけは推測で行っていません。** ダッシュボードはこの対応づけをもとに地図へ ▲ を置き時系列図に規制期間の帯を描くため、誤ると「規制のせいで交通量が落ちた」という誤った読み方を誘発します。裏付けが取れなかったものは対応づけせず、その理由を画面にそのまま出しています（例: 国道3号の最も近い観測点 `9110040` は規制開始より前から交通量がほぼ0で、規制中に回復しているため、この通行止めでは説明できない）。

### 規制を追加するとき

新しい報が出たら、PDFを `data/qsr_regulations/` に置き、本文を確認して `data/mlit_regulations.json` の `items` に追記します。本文の確認には補助スクリプトを使えます（`pymupdf` が必要です。ダッシュボードの動作には不要）。

```bash
pip install pymupdf
python scripts/dump_qsr_pdf_text.py            # data/qsr_regulations/*.pdf 全部
python scripts/dump_qsr_pdf_text.py road2-4    # ファイル名で絞り込み
```

追記する項目の形式と注意点はスクリプトの docstring にまとめています。観測点がどの路線上にあるかは OSRM の nearest で確認できます。

```bash
curl -s "https://router.project-osrm.org/nearest/v1/driving/130.97624,32.91327?number=3"
```

区間の線形を作るには、端点のICを [`scripts/build_mlit_paths.py`](../scripts/build_mlit_paths.py) の `IC_NODES` / `SECTION_ENDPOINTS` に追加して実行します。ICの座標は Overpass API で探せます（ノードIDを固定値で持たせ、実行ごとに結果が揺れないようにしています）。

```bash
python scripts/build_mlit_paths.py --dry-run   # 延長の差を確認
python scripts/build_mlit_paths.py             # data/mlit_regulations.json に書き込む
```

**② 収集開始が本震より後（時間的な欠落）**

規制情報の収集を始めたのが本震の翌日であるため、県管理道路であっても**それ以前に解除された規制は残っていません**。アーカイブに記録が残っている最も古い時点はダッシュボード上に表示しています。
